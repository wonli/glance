# OCR 云端试验包

独立 Go 包，仅使用标准库。按 PaddleOCR 异步 jobs API 实现，默认模型 `PaddleOCR-VL-1.6`。这不是本地 PP-StructureV3；校对 UI 可启动云端 OCR，再调用只读 PDF—Markdown 对齐包。

- `Submit` 接收文件 reader 或 URL，上传至云端；本地文件通过 multipart 流式发送，避免将整份 PDF 复制到额外内存；`Options{}` 对应示例中的三个 false。
- `Status` / `Wait` 查询、轮询任务，支持 context 取消；取消只停止客户端等待，不取消服务端任务。提交不会自动重试，避免重复计费。
- `Results` / `ParseResults` 按服务返回顺序提取逐页 Markdown，保留图片 URL 和原始页面 JSON（供后续读取坐标等字段）。Number 是输出顺序，不是书籍印刷页码。
- 不下载图片、不写入文档、不存储凭据。结果存储请求不携带 API 令牌，拒绝 HTTP 重定向。
- `Source.Size` 可提供文件长度以发送 Content-Length；未提供时由 HTTP 传输使用流式分块请求。默认单请求超时为 30 分钟；调用者仍应设置整体 context 超时或取消。

## 校对 UI 的缓存与恢复

云端客户端本身不保存 OCR 结果或令牌。校对 UI 的本地 OCR 缓存只在整本页面结果完整后写入，按 PDF 内容哈希、模型、选项和页数校验；缓存内容是 OCR 页面文字与版面数据，不包含依赖 B 草稿的对齐范围。缓存命中会跳过令牌读取和云端任务，并针对当前 B 草稿重新运行对齐；缓存缺失、损坏或页数不完整时继续使用云端识别与任务恢复流程。

缓存版本 2 保存服务实际返回的完整 JSONL 记录及逐页原始结果，包含未知的嵌套字段和资源引用；本机字符坐标作为附加信息保存，原始 JSONL 记录不被改写。逐页任务和整本任务均采用此格式，旧版本缓存不视为完整结果。单个缓存文件超过 64 MiB 时写入失败并报告缓存错误，不截断结果；结果仍可在当前会话使用。保存的是结果 JSON 中的资源引用或内嵌数据，不会额外下载 URL 指向的资源，也不包含任务轮询 HTTP 响应。当前实现为同一 JSONL 记录中的每个页面保留一份完整记录，多页同记录可能增加磁盘占用。

中断后的云端任务通过已保存的任务 ID 继续轮询。它与完整结果缓存是两种恢复机制：尚未完成的页面结果不会作为本地 OCR 断点复用。缓存命中和新识别结果会使用相同的候选搜索进度与全局路径对齐流程。

校对 UI 将首尾 `matched` 锚点、暂定歧义范围及边界状态显示为复核证据；点选 OCR 区块可查看 X 中对应的 B 字符。联动和高亮为只读视图，不会自动改写文稿或分页。UI 令牌由系统凭据库保存，缓存只保存 OCR 结果，不包含凭据。

从仓库根目录运行（令牌由调用环境提供）：

```sh
# 先在本机环境中设置 PADDLEOCR_TOKEN，不要把令牌写入仓库。
go run ./cmd/ocrprobe -file /absolute/path/sample.pdf -timeout 30m
# 或 -url https://example.com/sample.pdf
```

stdout 输出分页 JSON，stderr 输出任务 ID 与进度。调用会向 PaddleOCR 服务发送文档内容。业务调用必须在后台任务中执行，不能放在 Gio layout/frame 中。

校对窗口会在用户确认后上传完整 PDF。首次输入的令牌保存到系统凭据库，供后续任务复用；云端客户端本身不会读取或保存令牌。测试兼容服务时可设置 `PADDLEOCR_ENDPOINT`，否则使用官方默认端点。OCR 页数与 PDF 页数不符时，UI 拒绝建立物理页码对应。

针对性验证：`go test ./internal/ocr ./cmd/ocrprobe -count=1`。测试使用合成令牌和本机 HTTP 服务，覆盖文件/URL 提交、轮询、取消、异常状态、JSONL 分页和结果请求的令牌隔离；不证明实际古籍识别或 AB 定位准确。

## 2026-10-24 实际接口试验

用户指定的《唐诗汇评 增订本 4》PDF 共 892 页，约 206 MiB。本次仅将第 30 页渲染为长边 2400px 的 JPEG（约 274 KiB）提交默认云端接口，任务完成并返回 1 页 Markdown。识别内容以“卢纶”开头，页面末尾为“月香飘桂”。

对 OCR 结果和用户提供的 B 做临时匹配：仅保留 U+4E00–U+9FFF 汉字与数字后，OCR 的 363 个字符整体连续匹配 B 的归一化偏移 `[10558, 10921)`（零基、半开区间）。此处偏移不是原始 Markdown 的字符偏移，不可直接用于编辑；标点、版面或异体字准确性也未由这个结果证明。

该次单页试验只验证横排页面的云端识别与锚点检索，不代表整本或竖排准确率；当时也尚无自动首尾对齐 UI。原始 PDF/MD 未修改；临时图片和识别 JSON 已在验证后删除。后续相邻页、重复文字、竖排及夹注的局限由 `internal/textalign` 的六页实测记录说明。

## 对齐试验入口

`Page.Layout()` 提取结构化版面（文字块、坐标、竖排标签、阅读顺序），保留空图片区域。独立的 `internal/textalign` 与 `cmd/alignprobe` 可作只读定位；状态和真实前六页限制见 `../textalign/README.md`。UI 展示扫描光带和 OCR 块状态；仍不自动应用分页。
