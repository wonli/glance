# OCR — Markdown 定位实验

只读算法包。校对 UI 使用它把 OCR 页面文字定位到 Markdown B 的 Unicode rune 范围；该定位只提供证据，不修改 B、不提交分页、不标记已校对。

## 实际采用的方法

- 字符 2/4-gram 倒排索引找候选窗口，中文不依赖英文分词。
- KMP 优先匹配完整文字块，避免对长且无变化的片段做平方级计算。
- Smith–Waterman 局部动态规划处理文字块中的错字、漏字和多字。目前使用线性 gap penalty，尚未实现 affine-gap 或完整 RETAS。
- 多块在未使用的 B 区间中匹配，允许块顺序不同；单字碎片不提供独立定位证据。
- 角色识别排除页眉、页脚和印刷页码；可定位的文档标题锚定到 Markdown 标题，避免使用正文里的同名提及。
- 最大片段和算法选择连贯的文字块组，对组间无法解释的 B 字符扣分；允许页内换序，不跨区搜集名字凑覆盖率。
- 字符频次交集提供可接受匹配数量的上界；无法达标的窗口可安全排除。父窗口最优对齐完整落入子窗口时复用，避免重复 DP。
- 跨页候选图使用 Fenwick 前缀最大值做动态规划，求保留候选中的最优路径；反向分数及排除某页的替代路径用于判断歧义。允许跳过 A 页，禁止选择范围逆序或重叠。B 的间隙保持未分配。

这是借鉴锚点分治和文本校勘的组合原型，不是移植 Genalog/CollateX。暂未加入额外 AI 判定。OCR-VL 的输出只是识别证据，不能作为原文真值。

`Align` 可按 A 页报告候选搜索开始/完成进度，随后报告全局路径阶段。进度不代表已确认匹配；UI 等待全局路径完成后才发布可选对齐结果。`PathChoices` 只包含全局最优路径求解支持的替代范围，不是局部候选排序，也不表示概率。UI 用这些范围提供 A 区块到 X 文本的只读联动；高亮、滚动和候选切换不会编辑 B 或页面归属。

## 坐标与状态

Goldmark 提取文本节点，排除图片、链接目标和 HTML；保留匹配字符到 B 原始 Unicode rune 位置的映射。实体解码使用完整 Markdown 实体，保留整个实体源码范围，禁止将一个实体拆给两个匹配。只忽略标点/空白及语法、折叠大小写/全角 ASCII，不做繁简或异体字替换。范围为零基、半开 rune 区间，绝不能当 UTF-8 byte 或 UTF-16 偏移使用。

`matched` 表示当前搜索内存在充分定位证据，`ambiguous` 表示换序、覆盖不足、竞争路径或未识别图片等，`unmatched` 没有选择对应位置，`limited` 搜索达到预算。分数不是正确概率；覆盖率只针对已识别且参与匹配的字符，不包括图片中的漏识别文字。

所有 `ExactBoundary` 均为 false：文字证据的端点不决定邻近标点、Markdown 标记、空白或图片的页面归属。只读 `BoundaryAfter` 切分包络会显示为 `point`、`range` 或 `unresolved` 复核证据；它不能自动拆页或改变字符归属。实际分页编辑和提交仍需单独确认并通过工作区的撤销、版本检查流程。

## 运行

```sh
go run ./cmd/alignprobe \
  -ocr /path/p1.json,/path/p2.json,/path/p3.json,/path/p4.json \
  -md /path/book.md -first-page 1
```

输入是 `ocrprobe` 输出的 JSON 数组。文件必须是连续 PDF 页并按原始顺序排列；命令从 `first-page` 连续编号，无法从独立图片任务的 Number=1 反推出真实页码，不支持任意跳页编号。它不联网、不写文件，stdout 输出 JSON 证据报告。

默认每页 400 万对齐工作单位（包含线性预匹配与 DP 单元），可用 `-max-cells` 调整，硬上限1600万。默认候选12，`-candidates` 上限64。旧 `BeamWidth` 配置保留但不再参与算法。`MaxPathWork` 默认100万次候选访问、硬上限400万，限制跨页最优路径及替代路径检查。标题查找每页另有64000线性工作单位和每种标题256次出现上限；先检查输入大小，单字不作为独立定位标题。截断必须报告，不能当唯一匹配。单次最多2000页，OCR 单页最多12000归一化字符/512块/128KiB原始文字，B 最多8MiB。

这些是试验限额，不是整本性能承诺：Markdown 解析及索引构建尚不能即时取消，且其内存不受 MaxCells 约束；首次扫描大文档仍应观察资源使用。每页局部候选、标题角色和连贯性评分仍是启发式，不保证找到所有阅读顺序；标题约束只在 OCR 标题能在 Markdown 标题中完整找到时启用。低覆盖候选可保留作预览（最低25%），低于85%绝不标成 matched。Markdown 的代码块、自动链接等非普通正文暂不完整支持。

## 第三轮：内部锚点、连续页联合对齐与边界区间

### 算法

1. 对长续页（至少64个归一化字符）先找两个在查询和B中都唯一、距离足够远且同向的16字符片段，约束候选窗口，再进入原有块级对齐。这是检索启发式；使用该范围的结果始终 ambiguous，不能借此声称全文候选已经穷尽。查找有每页64000比较工作单位上限。
2. 从局部覆盖至少90%、有近优路径证据的页面提取内部唯一锚点，避开查询边缘最多8字符，避免把重叠页边的重复字锁死。所有保留的近优候选都必须支持该锚点。旧整页候选互相重叠、路径暂时跳过某页时，也可用其近优内部证据定位；不同页锚点源位置冲突则双方都放弃，不挑一边硬配。
3. 相邻锚点间最多8个连续物理页，以固定两端的全局单位编辑距离（匹配0、替换/插入/删除1）联合对齐。只为完整的中间页补充 `Joint` 候选，仍标 ambiguous；整页删除不会产生虚构对应。已知换序、缺少可读文字、非连续物理页不走这条线性对齐路径。
4. 用正向矩阵与反向行代价，求每个查询分页位置上所有最优路径的B切点包络，保留删除/重复字产生的多解。过滤会拆分实体（如 `&fjlig;`）的切点。相邻证据回退路径同样要求头尾可定位、页面身份有支持且无未识别图片。

`Anchor.Range` 是 B 原文 rune 半开范围；`Anchor.QueryRange` 和 `Evidence.QueryRange` 是 OCR 块中归一化字符的半开范围，不是原始 OCR 字节或逐字坐标。图片位置仍为块级坐标，不支持假装精确到单字的连线。

`BoundaryAfter.Min`/`Max` 与字符范围不同，是**两端都包含的 B 原文字符间切点**：`point` 表示文本模型下单个切点，`range` 是可能切点的包络，`unresolved` 表示没有足够证据（此时忽略数值字段）。包络可能包含不适合直接拆分Markdown语法的位置，不能直接当作可提交的页界；即使 point，`ExactBoundary` 仍为false。

联合DP默认总计200万正反向单元，硬上限800万，可用 `-joint-cells` 或 `Options.MaxJointCells` 调整；失败只影响相应物理边界，不抹去其他已求出的区间。context取消覆盖各页、锚点和DP行；源文解析/初始索引仍不保证即时取消。

## 2026-10-25：校对 UI 联动

校对 UI 复用本算法输出的候选搜索进度和全局 `PathChoices`。进行全局对齐前只显示当前候选搜索页与完成数；全局路径阶段单独标识。完成后只把 `matched` 页作为首尾确认锚点，`ambiguous` 页另列为暂定证据；`point`、`range` 与 `unresolved` 边界只供复核。

OCR 页面上只有有全局路径证据的文字块可以点选。点选会在 X 中高亮对应 B 字符并滚到其当前归属页；歧义时可在全局支持的候选间切换。联动不改写 B、字符归属或已校对状态。上述交互提高了证据可见性，不会把本节同一书六页的实验提升为全书或跨书准确率结论。


## 联合对齐内存优化

联合 DP 使用两行滚动距离、每单元一个字节的回溯方向，只为请求的分页行保存正向距离。保持单位编辑距离、对角/删除/插入的平局优先级、全部最优切点包络和实体切点过滤不变；计算预算仍按原有正反向单元计费。对 n×m 单元和 k 个不同分页行，主要存储从约 4nm 字节降为 nm + 4km + O(m)，时间复杂度仍为 O(nm)。此优化适合实际联合窗口中少量分页行；若请求所有行，检查点仍会占用完整距离矩阵大小。

Apple M1 上的合成基准（1000×1000 字符、每37字符一处替换、两个分页行，200ms × 3轮）：新实现约 1.10 MB/op，原实现约 4.10 MB/op，分配字节减少约73%；耗时分别为6.14–6.77ms与6.75–6.84ms。性能数值仅代表该基准，不代表整书速度或识别准确率。

`joint_optimization_test.go` 保留旧完整矩阵作差分参考：300组固定种子用例比较回溯配对和切点，覆盖空输入、重复/无效分页行、无分页行及切点过滤；既有穷举编辑路径回归提供独立校验。分配上限回归在旧实现约4.10MB时失败，新实现通过。可用 `go test ./internal/textalign -run '^$' -bench '^BenchmarkJoint' -benchmem` 复测。此轮未接UI、未修改原始文档，也未重新运行真实书籍OCR。
