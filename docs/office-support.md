# Office Preview and Editing Status

This status describes the current desktop implementation. A dependency's advertised feature set is not counted as an application feature until the UI and round-trip path are wired and verified. Multi-document workspace behavior is documented below; a feature's workspace persistence does not imply stronger Office format fidelity.

## Current desktop command

Run `make run-desktop` from the repository root. On macOS, this target suppresses Apple's duplicate Objective-C library warning from the Gio and native print cgo dependencies. Gio renders the window directly. Use the `+` tab menu to open a file or folder, create a draft, or save/Save As. The Word File ribbon also creates a blank DOCX draft, opens the shared office-file picker, switches to the workspace Recent page, edits supported document information, invokes DOCX Save As, exports a local DOCX copy through Share, and opens local Word version history; canceling file pickers leaves the active document unchanged. Share flushes pending body drafts and writes a revision-checked copy without adopting its path or clearing its dirty state. Its AutoSave toggle is per Word tab and restored with the workspace view state. When enabled, successful edits save asynchronously to the source DOCX; unsaved drafts remain protected by workspace recovery snapshots until Save As supplies a source path.

## Workspace

| Feature | Status | Current boundary |
|---|---|---|
| Permanent Recent tab and document tabs | Implemented | Gio-native horizontal `widget.List` at the top edge of the full-height content area; where Gio reports client-side decorations (macOS, Windows, Wayland client-side mode), the tabs occupy the transparent titlebar area with custom window controls and a dedicated move strip. X11 keeps its native titlebar because Gio's X11 backend forces server decorations. Tab title and close control share one tab surface, and `+` follows the final tab. Tabs retain their `documentSessionState` including editor and scroll widgets while inactive. Dirty tabs cannot be closed until saved. |
| Recent files and shallow folder listing | Implemented, basic | Local paths and supported direct children are saved to SQLite; missing recent files can be removed. Folder scan is non-recursive. |
| Drafts and Save As | Implemented, basic | Blank XLSX/DOCX/JSON drafts are recoverable. Save As validates `.xlsx`, `.docx`, or `.json`; cancellation leaves the draft intact. |
| Restart recovery | Implemented, basic | SQLite stores self-contained adapter snapshots, dirty state, tab order/active tab, and view state. Missing original paths keep the snapshot and show an unavailable-source status. Gio does not expose a cancellable pre-close event, so closing the window cannot prompt before OS shutdown. |
| Word version history | Implemented, local DOCX snapshots | Each canonical source path has its own timeline in the workspace SQLite database. Opening a file records a baseline; successful manual/automatic saves and Save As record the exact DOCX bytes written. Same-path SHA-256 snapshots deduplicate; autosave snapshots are limited to one new version per five minutes. The File history list asynchronously reads metadata (local time, source, byte size); full package BLOBs load only for restore. Restore asks for confirmation, saves the current package first, and enters Word undo/redo as one operation. Each path retains at most 50 versions or 512 MiB and prunes oldest records. File-save and history-write failures are reported separately. The SQLite payloads are plaintext and local; encrypted DOCX, cloud sync, and other formats are unsupported. |
| Word View > New Window | Implemented in code; native interaction pending | `TestWordNewWindowActionOpensSharedDocumentView`, `TestPrimaryWindowPromotionAndFinalShutdown`, and `TestSessionResultFansOutAfterOriginWindowCloses` cover a shared document session, independent views, primary promotion, teardown, and late-result fan-out. Only the primary view persists shared active/view state; other views are runtime-only. On 2026-10-03, macOS CUA opened a local DOCX and the View ribbon, then returned `noWindowsAvailable` after the New Window interaction before the second window or close/edit behavior could be inspected. macOS, Windows, and Linux are not marked runtime-verified. |

Native file/folder/save dialogs and shallow folder scans run asynchronously. Folder recents are staged in memory and written as one batch through the background workspace writer. Workspace snapshot serialization and SQLite writes also use that writer so Gio frame layout stays responsive; it drains queued work on shutdown. Snapshot serialization is performed by the format adapter and still needs continued stress testing with large workbooks and concurrent editing.

## XLSX

| Feature | Status | Current boundary |
|---|---|---|
| Open workbook and switch worksheets | Implemented | `.xlsx` only. |
| Preview cell values | Implemented, virtualized | Full legal XLSX address extent (1,048,576 rows × 16,384 columns), rendered from the visible window with two rows/columns of overscan. Horizontal and vertical scrolling are supported; blank cells outside the used range can be selected. Opens and range reads run off the Gio frame loop. Scrolling replays bounded cached cell paint operations using full cell bounds, so clipping at the viewport edge does not change text layout; cached operations are rebuilt when value, style, size, or display scale changes. Gio still composites each frame. |
| Cell styles and formatting toolbar | Partial, editable | Home applies bold, italic, underline, font/fill colors, horizontal alignment, General/integer/two-decimal/date formats, four border presets, and clear format to the selected rectangle. XLSX style patches preserve untouched style properties and save/reopen tests cover mixed styles. Rendering includes common colors, font family, bold/italic/underline, alignment, wrapping, and borders. Number formats affect workbook data but are not fully rendered as Excel would; theme/indexed colors, rich text, conditional formatting, and Excel-perfect typography remain unsupported. |
| Merged cells | Partial | Visible merge ranges render as the anchor cell across rows/columns, clipped to the viewport. Clicking an interior selects the anchor. |
| Edit a cell constant | Implemented, basic | Click selects; double-click or F2 opens an editor over the cell. The editor retains the rendered font color, weight, style, fill, alignment, and wrapping while keeping the same cell bounds. Enter commits, Escape cancels. The name box and formula/value bar track the active cell. Text, finite numbers, booleans, and blanks are supported; formula-like input is rejected. |
| Clipboard copy/cut/paste | Implemented, plain TSV | Home copies or cuts the selected rectangle through Gio's system clipboard and pastes TSV at the selection's top-left cell. Empty fields, quoted tabs/newlines, and ragged rows are preserved. Paste is capped at 10,000 cells and rejected atomically if it exceeds the XLSX edge; formula-like input is rejected. Cut clears contents while retaining source formatting. Styles are not copied with clipboard data. |
| Undo and redo | Implemented, session scope | Cell constant edits, format patches, paste/cut batches, row/column and sheet structure edits, and sorting are reversible in the open workbook session. History retains up to 100 workbook snapshots. Successful save rebases history; later edits can still be undone. |
| Row/column and worksheet structure | Implemented, basic | Home inserts/deletes one row or column at the active cell. Worksheet tabs support create, rename (enter the name in the adjacent field), and delete; the last sheet cannot be deleted. Operations refresh the virtual grid and are undoable. Formula-reference rewriting outside tested XLSX behavior is not promised. |
| Sort selected range | Implemented, bounded | Data sorts the selected rectangle by the active column, including its first row. Finite numeric strings sort numerically, text sorts case-insensitively, and blanks remain last in ascending order. Row cell values and styles move together. Ranges containing formulas or merged cells are rejected; ranges are capped at 10,000 cells. |
| Value filter | Implemented, transient | Data hides rows in the selected rectangle that do not exactly match the active cell's displayed value; the first selected row remains visible as a header, and blank matches are supported. Clearing restores row heights. Filters reset when switching worksheets or workbook tabs and do not modify XLSX data. The selected range is capped at 10,000 cells. |
| Embedded over-cell pictures | Implemented, first edit slice | Common PNG/JPEG/GIF (first frame) drawings render above the virtual grid, preserve aspect ratio, follow scroll/scale/row/column geometry, and clip to the grid viewport. Insert Image uses a native asynchronous picker and places the picture at the active cell or a nearby free anchor. Select a picture for contextual replace/delete/width controls; drag to move or use the resize handle. Picture bytes and adapter metadata are loaded off the Gio frame loop. Single ordinary pictures at a unique cell anchor are editable; duplicate anchors, in-cell/`DISPIMG`, unsupported media, and other drawing kinds remain visible when possible and read-only. |
| Picture edit and save/reopen | Implemented, fixture round-trip verified | Adapter tests cover insert, replace, move, ratio-preserving resize, delete, undo/redo, save/reopen, and preservation of unrelated image bytes, formulas, styles, merges, and row/column dimensions. The picker UI regression inserts a PNG through the asynchronous result path and verifies the saved/reopened image bytes and anchor. Source samples are only opened and saved through temporary copies. This is not a universal Office-part preservation guarantee. |
| Save edited workbook | Implemented, synthetic round-trip verified | Background save through a sibling temporary file then replacement. Adapter tests reopen synthetic workbooks after cell, style, clipboard, structure, sort, and picture edits; representative untouched values, styles, merges, formulas, dimensions, and pictures survive. The local corpus check succeeds for the valid samples but cannot open `人事表格-员工绩效表.xlsx`: Excelize rejects malformed `xl/styles.xml` where `<font>` is closed by `</name>`. The original sample remains unchanged. |
| Formula calculation and broad formatting edits | Not implemented | Cached values may display through Excelize; formula calculation and full Excel layout are not promised. |
| Resize row heights / column widths | Implemented, fixture scope | Drag a row/column heading boundary. Preview geometry and cursor remain active during drag; cancellation or write failure restores prior dimensions. Only release writes dimensions. Pixels convert to points/Excel character widths; XLSX limits are enforced. |
| Legacy `.xls` | Read-only, limited | Opens the first worksheet only. The supplied `.xls` sample contains three empty sheets, so it verifies package opening but not cell-value fidelity. Editing/saving is disabled. |

## DOCX

| Feature | Status | Current boundary |
|---|---|---|
| Preview body paragraphs, tables, styled runs, and inline pictures | Implemented, paginated and web-flow views | Continuous and Print Layout use the same accepted `internal/wordlayout` page scenes for text wrapping, page breaks, table fills/borders, paragraph spacing, and image positions. Continuous view stacks those pages with a compact separator; Print Layout adds paper gaps and shadows, and may arrange two pages per row. The shared page scene is editable in both modes for supported text runs and inline images. Web Layout remains a separate responsive flow view, with the horizontal and vertical rulers and canvas-width drag behavior. PNG/JPEG previews are decoded, GIF uses its first frame, and unresolved/unsupported media appears as a placeholder; missing image media parts produce a warning rather than blocking the document, with a placeholder when source dimensions are usable. Floating drawings, headers/footers, text wrapping around images, multiple sections/columns, and other diagnosed constructs are not represented by the page engine. |
| Project Word page/style metadata | Implemented, projection only | The neutral DOCX adapter projects section start positions, page dimensions/orientation/margins, `docDefaults`, style inheritance links and explicit style masks, including the default paragraph style when a paragraph omits `w:pStyle`, paragraph spacing/line rules/indents/keep controls, and table grid/cell widths. If `w:orient` is omitted, page orientation is inferred from explicit width and height; only an explicitly supplied unknown value is diagnosed. Zero-width body range annotations such as bookmark, proofing, comment, and permission markers are ignored by the neutral block projection; the original OOXML parts remain preserved in the DOCX package. Projection is read-only and leaves snapshot bytes/dirty state unchanged; the shared layout engine consumes the supported subset to calculate pages. Multiple sections/columns, character-based indents, merged/nested tables, and repeated table headers are located as unsupported; see Shared Word page layout for current diagnostics and output gating. Revision-, draft-epoch-, and page-setup-keyed layout runs in a background worker. Continuous and Print Layout replay the same page scenes; the presentations differ only in page surfaces, gaps, shadows, and optional two-page arrangement. The page scenes retain cell fills, borders, glyph geometry, and image positions in both modes. Clicking and editing supported text runs, selection, keyboard navigation, and supported image selection/resize/rotation use the scene's page-space coordinates in both modes. View > Reading Mode preserves the current continuous/print/web mode, scroll, zoom and status bar while hiding the Ribbon, rulers and screen gridlines; body text and image editing are disabled until the explicit exit button restores the previous view. View > Gridlines adds a faint, screen-only overlay to continuous and print-layout pages; it does not modify the shared `PageScene` used by PDF/print. View > Navigation Pane displays Heading 1–9 paragraphs and custom styles inheriting from them, plus live case-insensitive search results in editable text runs; it shows the total count and at most the first 500 results, reuses the index until the query/revision/draft epoch changes, and selects the run range or scrolls to its current paginated page. Cache hits do not scan retained editors. Search is limited to one editable run and skips read-only fields. View > Single Page enters Print Layout and fits the current page to the viewport. View > Multiple Pages displays two pages side by side per vertically scrollable row; an odd last page is centered alone. Manual slider/button/dialog zoom exits either automatic fit preset. Status zoom remains 50%–150%, so very short viewports may still need scrolling. These view changes leave DOCX content unchanged. Web Layout retains its separate canvas behavior. Pen's actual screen comparison remains pending. The engine currently supports one section and common paragraph/run/list/image content plus ordinary row-splitting tables; unsupported floating drawings, headers/footers, wrapping around images, multiple sections/columns, and several table constructs remain diagnosed or limited. |
| Export Word PDF | Implemented, limited | `internal/format/pdf/word.go` replays `PageScene` page sizes, glyph outlines, font color/highlights/underlines, table borders, and PNG/JPEG image boxes/rotation without reflow. | Edit text and add body paragraphs | Implemented, supported runs | Clicking editable text places the caret in a persistent editor at that position without painting a selected-run background. | Password-to-open encryption | Not implemented; deferred pending CFB/read-path and recovery review | Excelize v2.11.0 writes Standard AES-ECB/SHA-1 encryption and its Agile decrypt path does not validate Agile package HMAC, so it is not safe for this feature. No dependency is selected. Workspace snapshots currently store plaintext DOCX ZIP bytes in SQLite; file encryption alone would not protect recovery data. A complete design must cover encrypted open/save/autosave/Share/workspace recovery and password re-entry after restart. Keep File > Protect Document disabled until those paths are reviewed and validated. |

## Regression with the local sample folder

To include the user's local files without checking them into the repository:

```sh
GOCACHE=/tmp/glance-go-gocache GLANCE_OFFICE_TEST_DIR="$HOME/Downloads/office" go test ./...
```

The tests open and save copies of `.xlsx`/`.docx` samples, reopen the copies, and leave originals untouched. The `.xls` sample is opened read-only. `.ppt` and PDF files are outside this first desktop slice.
