# Office Preview and Editing Status

This status describes the current desktop implementation. A dependency's advertised feature set is not counted as an application feature until the UI and round-trip path are wired and verified. Multi-document workspace behavior is documented below; a feature's workspace persistence does not imply stronger Office format fidelity.

## Current desktop command

Run `make run-desktop` from the repository root. On macOS, this target suppresses Apple's duplicate Objective-C library warning from the Gio and native print cgo dependencies. Gio renders the window directly. Use the `+` tab menu to open a file or folder, create a draft, or save/Save As. The Word File ribbon also creates a blank DOCX draft, opens the shared office-file picker, switches to the workspace Recent page, edits supported document information, invokes DOCX Save As, exports a local DOCX copy through Share, and opens local Word version history; canceling file pickers leaves the active document unchanged. Share flushes pending body drafts and writes a revision-checked copy without adopting its path or clearing its dirty state. Its AutoSave toggle is per Word tab and restored with the workspace view state. When enabled, successful edits save asynchronously to the source DOCX; unsaved drafts remain protected by workspace recovery snapshots until Save As supplies a source path.

Native file/folder/save dialogs and shallow folder scans run asynchronously. Folder recents are staged in memory and written as one batch through the background workspace writer. Snapshot serialization is performed by the format adapter and still needs continued stress testing with large workbooks and concurrent editing.

## Shared Word/Excel font library (2026-10-15)

Word and Excel share the compact font picker, local font search (including parsed Chinese aliases), document-font summary, inline previews, cache state and manual refresh/retry. Missing document families remain named and marked missing; choosing a replacement goes through the existing formatting command. The Ribbon displays the selected run/cell family. Downloading alone does not modify a document.

Supported system discovery covers readable TTF/OTF/TTC/OTC resources reported by platform font directories, including metadata for large macOS collections. Individual invalid files are skipped with diagnostics. This is not a guarantee that every protected OS font, collection face, variable/color font or PDF embedding mode can render/export. Gio custom font collections are limited to 128 MiB; its fallback and Word's script/compatibility rules remain distinct renderer adaptations.

Online support is implemented behind `fontdownload.Provider`; the initial production manifest is empty. No public font catalog or network download is advertised in the UI until verified entries are supplied. Downloads currently accept single-face static TrueType fonts (64 MiB maximum), with a fixed version, license, HTTPS URL, SHA-256 and expected family. Files remain private to Glance. DOCX/XLSX save canonical family names and do not embed these fonts; another application/machine still needs an equivalent font.

Excel's summary reads the workbook's declared style-font table, including offscreen styles. It can include unused declarations and does not promise a complete rich-text-run inventory. Word's summary follows the neutral projected text runs, so unsupported original package content is outside that summary. Neither summary is a new full Office text engine.

Evidence and limits, including full-suite baseline failures and native-input coverage: [font-library-verification.md](font-library-verification.md).

### Word formatting responsiveness (2026-10-18)

Selection mutations publish blocks and their committed-text baseline together. UI editor draft collection checks the view's text-reset epoch and run membership under the text-state lock, so a frame overlapping undo/redo cannot reintroduce removed run IDs or submit text from an older structure. Synchronization retires removed editors without discarding existing recovery drafts; history reconciliation clears previous range endpoints and input snapshots. These safeguards have been compiled; native-window reproduction of repeated formatting with undo/redo remains pending.

The font-size field participates in the persistent Ribbon click/event path and offers preset/custom sizes. Selection formatting preserves paragraph-level bookmark markers while changing runs (save/reopen and undo are covered), and preserves refusal during pending selection edits or IME composition; it must not fall back to formatting the whole run. Initial pagination can publish progressive pages; reflow keeps the accepted page scene and scroll position until the final result. Font candidate order is reused across text runs, with a bounded family/weight/style cache independent of size/color. Gio font loading parses only the requested TTC face and keys parsed resources by file identity and face index, avoiding eager parsing of unrelated collection faces. Catalog-based Word fallback checks cmap coverage before parsing complete glyph tables, so fonts rejected for missing characters are not retained as loaded faces. These changes do not establish a fixed process-memory ceiling; live Go heap and process/GPU memory need separate measurement.

Formatting controls and the page editor reuse inherited scene typography (paragraph/default/character styles), overlaying newer direct properties during reflow. Size arrows therefore step from the displayed effective size instead of a fixed fallback. DOCX no-op checks resolve the same inheritance before discarding formatting patches, allowing explicit false overrides of inherited bold/italic/underline. The supplied local reproduction has no direct run sizes: body paragraphs inherit 12pt and table paragraphs 10.5pt; the renderer must preserve those values. Rendering differences caused by font substitution and rasterization still require comparison at the same zoom and device scale.

When `eastAsia` is absent throughout style inheritance, Word shaping uses the platform CJK default instead of treating `ascii`/`hAnsi`/`cs` as a Chinese font request; explicitly set East Asian families are preserved. This follows the application-defined script-default boundary described in [Microsoft's rFonts implementation notes](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oi29500/aef3c9a6-5d6c-434b-90b7-85e761fd8e62). WPS may choose a different default family, so this does not establish exact glyph or pagination parity. `TestMissingEastAsianFamilyDoesNotReuseLatinOnlyFamily` covers the script mapping; `TestWordCJKTypographyPreview` can render a synthetic, same-size GPU comparison when `GLANCE_WORD_TYPOGRAPHY_PREVIEW` is set.
