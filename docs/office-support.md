# Office Preview and Editing Status

This status describes the current desktop implementation. A dependency's advertised feature set is not counted as an application feature until the UI and round-trip path are wired and verified. Multi-document workspace behavior is documented below; a feature's workspace persistence does not imply stronger Office format fidelity.

## Current desktop command

Run `make run-desktop` from the repository root. On macOS, this target suppresses Apple's duplicate Objective-C library warning from the Gio and native print cgo dependencies. Gio renders the window directly. Use the `+` tab menu to open a file or folder, create a draft, or save/Save As. The Word File ribbon also creates a blank DOCX draft, opens the shared office-file picker, switches to the workspace Recent page, edits supported document information, invokes DOCX Save As, exports a local DOCX copy through Share, and opens local Word version history; canceling file pickers leaves the active document unchanged. Share flushes pending body drafts and writes a revision-checked copy without adopting its path or clearing its dirty state. Its AutoSave toggle is per Word tab and restored with the workspace view state. When enabled, successful edits save asynchronously to the source DOCX; unsaved drafts remain protected by workspace recovery snapshots until Save As supplies a source path.

Native file/folder/save dialogs and shallow folder scans run asynchronously. Folder recents are staged in memory and written as one batch through the background workspace writer. Snapshot serialization is performed by the format adapter and still needs continued stress testing with large workbooks and concurrent editing.
