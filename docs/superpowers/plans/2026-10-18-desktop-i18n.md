# Desktop UI Internationalization Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Localize every app-owned desktop UI surface in Simplified Chinese and English, support system language selection, and preserve existing document and widget state during a language change.

**Architecture:** `internal/i18n` owns embedded JSON catalogs and locale formatting; `internal/systemlocale` reads platform preferences; `desktopui` owns the selected/resolved locale, settings interaction, and localized message references. UI behavior uses stable IDs and explicit feedback metadata, while adapters and document data remain language-neutral.

**Tech Stack:** Go, Gio, `go:embed`, `encoding/json`, `text/template`, existing `golang.org/x/text`, existing workspace SQLite preferences.

**Spec:** `docs/superpowers/specs/2026-10-18-desktop-i18n-design.md`

## Global Constraints

- Supported selections are `system`, `zh-CN`, and `en-US`; unsupported or unreadable system language and invalid stored selection resolve to `en-US`.
- Use embedded `zh-CN.json` and `en-US.json`; English is the complete fallback catalog.
- Persist `ui.language` in the existing preferences table; do not add a schema migration.
- Resolve messages in memory during rendering; do not parse catalogs, read system settings, or write preferences in Gio layout.
- Keep document contents, formulas, paths, MCP protocol identifiers, and model-generated conversation text unchanged.
- The basic settings page follows Pen node `l7WA9J` and contains only the supported interface-language row. Do not add theme, autosave, font, session-restore, or other unsupported controls from the design.
- Keep stable Gio widgets and preserve active document, drafts, selection, cursor, scroll positions, modal identity, and modal drafts while switching languages.
- Translate complete sentences with named parameters; never infer behavior from translated wording.
- Do not add translation-network dependencies; reuse dependencies already in `go.mod`.

## Review Focus

- Unsupported or malformed system/preference locale resolves to English; pin in `internal/i18n/locale_test.go` and `internal/desktopui/locale_preferences_test.go`.
- An asynchronous result arriving after a language switch renders in the currently selected locale; pin in `internal/desktopui/locale_switch_interaction_test.go`.
- Switching while a modal and editor draft are open preserves both and updates the visible copy; pin in `internal/desktopui/locale_switch_interaction_test.go`.
- External errors containing paths or source-language text keep the primary message localized and retain diagnostic detail; pin in `internal/desktopui/localized_error_test.go`.
- Long English labels in narrow windows at 1x/2x remain readable and clickable; pin in `internal/desktopui/settings_visual_test.go` and the locale visual cases.

**Interfaces:**

- macOS reads `CFLocaleCopyPreferredLanguages`; Windows uses `GetUserPreferredUILanguages` through existing `golang.org/x/sys/windows`; Linux checks `LC_ALL`, `LC_MESSAGES`, then `LANG`; other platforms return no tags. Each implementation parses tags with `golang.org/x/text/language`.

## Self-Review

- **Spec coverage:** Catalog format, fallback, system matching, persisted preference, Basic Settings placement, stable behavior IDs, asynchronous messages, UI formatting, every desktop feature area, error details, document safety, visual coverage, and documentation each map to Tasks 1–11.
- **Step scan:** Every task defines files, public interfaces or migration boundaries, named behavior checks, focused commands, and a commit point.
- **Type consistency:** `i18n.Message` is the common value stored by feedback and dialogs; `Selection` represents the persisted choice and `Locale` the resolved catalog, so `system` is never passed as a catalog locale. `PreferredLanguages` returns parsed `language.Tag` values consumed directly by `Resolve`.
- **Review Focus:** Unsupported language and malformed preference are covered in Tasks 1–3; late async completion in Tasks 3 and 7–10; open modal/draft preservation in Tasks 4–10; external error text in Tasks 5 and 11; narrow/long 1x and 2x layouts in Tasks 4 and 6–10.
- **Proportion:** The plan is split by shared infrastructure and existing UI ownership; format migrations stay independent after the message API is established, followed by one release audit.
