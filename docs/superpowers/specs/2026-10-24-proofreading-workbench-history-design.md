# 校对工作台、恢复与逐页 Git 历史

## 目标与已确定行为

按 Pen `kms7p` 添加校对列表，关闭后无需重新选择原稿，恢复上次页面和工作进度。每个任务有独立普通 Git 仓库（不是 Git worktree），原 PDF 与待校对稿复制到任务目录。SQLite 保存任务索引及可恢复工作状态；Git 只保存明确确认的逐页成果。允许按第 6、500、7 页等任意顺序校对，展示和导出始终按 PDF 页序。

## 方案

采用现有 workspace SQLite 加独立任务 Git 仓库。仅使用 Git 难以保存未确认进度和工作台查询；仅使用 SQLite 不满足用户要求的 Git 历史。原稿使用目录内文件，不作为每页提交的一部分。任务根目录包含 sources/、pages/ 和 .git/；pages/000006.json 等固定六位补零文件是同一页的持续版本。六位是最小宽度，不限制更大的页号。页面身份以文件内稳定 PDF 页 ID 为准，印刷页码不参与排序。

## 数据与边界

internal/workspace 承担版本迁移、任务元数据和恢复快照；新增独立历史服务封装受限 Git 命令。UI 不直接执行 SQL 或 Git。复用现有 SQLite 驱动和 managed background 生命周期，不在 layout 中进行复制、序列化、数据库或 Git 操作。

任务记录包括稳定 ID、标题、目录、原稿名称/哈希、总页数、最后打开时间、视图状态、恢复快照版本和错误状态。恢复快照保留完整中立校对模型、分页归属、当前 PDF 页、A/X 滚动及文本字号；工作副本恢复不依赖 Git HEAD。

历史字符身份必须跨版本唯一。当前 Undo 会回退 Next，需增加任务级持久化的单调字符分配水位，撤销不回退水位；旧快照恢复时提升至已知历史最大水位。不能仅凭可能重用的旧 CharacterID 推定历史来源。

逐页成果 JSON 包含 schema 版本、任务与原稿身份、PDF 页 ID、文本 runs 的稳定字符身份及归属、确认信息。仅导出目标页，不附带未确认页面的内容或 Reviewed 状态。Git 提交必须显式限定目标文件，禁止 git add .；本地作者身份由应用设置，不改用户全局 Git 配置，不添加远程、不联网。

## 确认、修改与故障

确认前同步已完成的编辑器草稿，IME 合成期间不得确认中间文字。捕获目标页不可变版本，在后台串行写入并提交，确认状态与快照状态独立；成功且内容版本仍匹配后显示“快照已保存”。失败保留已校对状态和工作进度，显示“快照失败，可重试”，不误报快照成功。重复确认完全相同成果不创建空提交。

已确认页继续编辑后显示“已修改，待确认”；保留上次成果及跨页保护，直到再次确认生成新提交。用户主动改为未校对时，工作状态明确更新；历史成果仍保留，不把旧成果视为当前确认。撤销/重做也依据当前内容与最后确认成果匹配情况计算显示状态。

快速连续确认按任务串行处理，不允许迟到结果确认较新的编辑。文件写入、Git 提交和 SQLite 不具备共同事务，需记录待提交状态并在打开任务时按目标页成果哈希和 Git 提交核对，支持失败重试，避免重复提交或虚假已确认。Git 不可用时仍允许确认已校对并保存当前工作进度，但明确标记“未生成历史快照”；不在 SQLite 中累积替代 Git 的确认快照，不补造安装前历史。安装后允许手动为已校对页创建首次快照。

## 校对者身份设置（Pen dKZjY）

工作台设置入口进入独立页面，包含返回校对列表、Git 用户名、Git 邮箱及“保存校对者身份”。复用稳定 Editor 与设置表单命中区域经验，保存到现有 SQLite preferences；成功反馈后跨重启恢复。姓名与邮箱必填，清除首尾空白，拒绝换行和 NUL，邮箱做基本格式校验，不要求联网验证。

身份为应用范围默认值。每次确认捕获当时已保存的身份，同时作为 Git author/committer 与成果确认信息；后台提交不得在身份更改后读取新身份。修改身份只影响将来的提交，不改写既有历史，不读写用户全局 Git 配置。未配置时允许导入、编辑、自动保存及标记已校对；创建 Git 快照前引导设置身份，不能伪造默认校对者。

远程认证纳入本次范围：可添加现有 SSH 私钥或生成专用于校对的新密钥，也可保存 HTTPS 用户名及令牌。令牌存系统钥匙串，SQLite 只存引用；SSH 私钥保留本机受限目录，展示公钥供用户配置服务端。凭据可跨项目复用，认证用户名与提交作者独立。不得把凭据放入成果、日志、仓库 URL 或 Git 提交。

每个任务单独设置远程 URL 和所选凭据，提供显式“推送”入口；需要 Git、匹配的认证及远程地址。仅允许普通非强制推送当前校对分支；不自动拉取合并、不覆盖远端分歧。首次 SSH 主机信任需展示指纹并由用户确认，不关闭主机校验。Git 操作禁止交互式密码挂起，并支持超时及取消。页面分别显示“已校对”“快照已保存”“已推送”；推送成功仅对应本次捕获的提交，之后产生的新提交仍待推送。认证失败或远端分歧不影响本地成果，并保留重试入口。用户本次授权的是实现推送功能，不是在开发验证期间向真实远程发送文件；测试使用本地临时 bare 仓库及合成凭据。

## 页序与跨页

固定 PDF 页 ID 决定顺序，Git 提交时间决定历史顺序。现有模型已阻止调整跨越 Reviewed 页；待重新确认的已修改页继续保留该边界保护。确认第 6 页绝不顺带确认第 1–5 或第 7 页。验证字符唯一归属，边界冲突必须报告，不静默改写其他已确认页。

历史恢复作为目标页的待确认修改；先校验字符归属，若与其他页面冲突则阻止并解释。恢复不得执行整仓库 reset/checkout 丢弃当前工作进度。

## 界面

应用主入口保留原主页与 Glance 标签。校对模块是独立窗口，在该模块内使用固定的第一个“文档工作台”标签；校对稿在同一窗口右侧以并列标签打开，标签布局复用主页。切换工作台不关闭稿件，关闭单稿不影响其他稿件，再次继续同一任务定位已有标签。不新增主页侧栏或校对工具栏入口。默认列表仅保留设计中的继续操作；任务历史沿用现有顶部历史入口，本页历史位于页菜单。kms7p 工作台使用真实任务列表，提供新建、继续及当前页、已确认页数、最后工作时间。先恢复列表，再按用户选择打开任务并恢复视图，不自动打开所有任务。

编辑区每页页眉显示文字和图标状态：未校对、已校对、已修改待确认、快照处理中、快照失败；Git 不可用时显示未生成历史快照。已校对页使用明确的勾选徽标和轻量页框强调，不能只靠颜色区分；当前页高亮与确认状态独立。页菜单允许确认修订，已校对但内容修改后不能因旧布尔状态阻止再次提交。顶部显示已确认页数/总页数。新增文案同时支持中文和英文。

提供单页历史与任务全历史入口，展示页码、时间、提交说明和文本差异；首版支持安全地将历史成果恢复为待确认修改。未确认页不编造成果。

## 兼容、安全与范围

旧草稿仅在可验证原稿身份的情况下导入，原草稿保留，不在迁移失败时覆盖。原稿复制成功且任务可恢复后才报告创建成功；源文件后续移动或删除不影响任务。包含手动远程推送；排除自动同步、Git 分支管理和多人合并。Git 只记录确认成果，普通自动保存不会生成提交。

## 验证

当前授权目录运行必要的针对性测试，复用现有缓存。覆盖 SQLite 迁移与重开、原稿移除后恢复、当前页和滚动恢复；6→500→7 的提交隔离和页序；同页修订/无操作确认；失败重试、迟到结果、进程中断协调；中文 IME、跨页保护、历史恢复冲突；1x/2x 状态标识及工作台真实渲染。实际窗口验证先退出旧 Glance，再使用 GLANCE_PPROF_ADDR=127.0.0.1:6060 go run ./cmd/glance。GPU 跳过不得报告视觉通过，验证临时产物在结束后清除。

校对状态显示位置（Pen `wiBkP`）：仅在底部 PDF 页码缩略图导航区，通过页卡边框、底色和短状态标签区分未校对、已校对、快照保存中/已保存/失败及修改待确认。当前页使用加粗边框，不把当前选中误作差异页。X 编辑纸张不绘制校对状态文字、彩色边框或状态底色；1x/2x GPU 回归比较校对前后 X 纸张像素一致。
