# OCR 任务恢复与 B 空白页补入设计

## 意图

让长 PDF 的整本 OCR 作业在应用退出后可从服务端任务继续查询，避免重新上传；识别完成后，将“PDF 有文字、校对稿对应页为空”的可信候选标色，并提供 OCR 文字预览，由用户确认后填入该 B 页。

## 当前状态与依据

- `internal/desktopui/proofread_ocr.go` 在提交后只于后台 goroutine 内持有 PaddleOCR job ID；进度、结果都存在内存 channel / `proofreadingOCRScan`，项目恢复数据没有 OCR 作业字段。
- 当前流程等 job 为 `done` 才下载完整 JSONL、运行全文 `textalign.Align`；PaddleOCR 官方 Go API 分开提供 Submit、按 job ID 查询状态和完成后取结果。本设计保持整本单任务，不承诺识别期间获得逐页正文。
- 校对项目已有 SQLite `proofreading_projects.payload` JSON 恢复负载，可加入向后兼容的 OCR 任务元数据字段，不新增 SQLite schema。
- 仓库已有 `agentsettings.SystemCredentialStore` 和 `workspace.Store.SetPreference`；OCR 令牌复用系统凭据库，ref 放到全局 OCR 偏好，不与项目 Git 远程凭据混用。
- A 与 B 页不假定页码相同。只有相邻已匹配文本能够把 A 页夹定到唯一的空 B 页时，才建立补入候选；不能唯一定位时只保留 A 页 OCR 状态，不替用户猜 B 页。候选同时绑定有序 B 页范围指纹，防止文本不变但分页边界变化后沿用旧目标页。

## 目标

- 服务接受上传并返回 job ID 后，将 job ID、服务端点/模型、A 源 PDF hash、B 文稿 hash、创建时间和任务阶段写入项目恢复负载。页进度在重开后从服务端状态重新查询，不逐页写 SQLite。
- 第一次扫描时通过掩码输入框取得服务令牌并保存到操作系统凭据库；之后新扫描和恢复任务都从凭据库读取，不重复询问。
- 全局 `proofreading.ocr.authentication` 偏好只保存凭据库 opaque reference 和对应 endpoint；项目 SQLite 恢复负载不包含令牌。更换 endpoint 时要求为新 endpoint 提供令牌，不把旧 endpoint 的令牌发到新地址。
- 重开同一项目时，hash 与当前 A/B 源一致才允许恢复；用与已保存 endpoint 匹配的凭据继续查询 job，不重新上传 PDF。
- 令牌只在取用和网络请求期间驻留内存，不进入日志或 OCR 结果。凭据库不可用、令牌不存在或服务拒绝认证时才重新询问；替换令牌成功后删除旧凭据。
- 作业完成后沿用现有整本结果下载与只读对齐流程。只给唯一映射到空 B 页的候选添加缺文颜色；点击 X 页顶部状态标签查看 OCR 文字和目标页码。
- 用户确认填入后，只写入所选空 B 页，走现有校对模型编辑、撤销/脏状态和自动保存路径；不自动标记为已校对。
- OCR 结果仍按服务返回的物理页序展示；匹配歧义或 B 页目标不唯一时保留未匹配/歧义状态，不显示可直接应用的填入动作。

## 非目标与限制

- 不拆分 PDF，也不提交多个 page-range 作业；不改变整本作业的等待行为。
- 不将服务令牌写入 SQLite、项目恢复负载、源文件或日志；凭据库读取/写入不能发生在 Gio layout/frame 中。
- 不在网络提交期间崩溃后续传尚未获得 job ID 的文件上传。
- 不自动将 OCR 文本写入 B，不覆写非空页面，不自动改变页边界或已校对状态。
- 本阶段持久化远程 job 元数据，不承诺长期本地保存整本 OCR JSONL。若应用在取回结果后、页面状态保存前退出，将使用同一 job ID 重新获取结果；服务端结果保留期限需以实际 API 行为为准。

## 方案与已选方向

### 长任务恢复

1. **整本任务 + 持久化 job ID（已选）**：实现改动小，重新打开后继续轮询且不重复上传；页面对齐仍等整本结果。
2. **分段 OCR 并逐段对齐**：更早显示结果，但需要 PDF 分段、更多服务任务与页码重映射，当前阶段不做。

### B 空白页

1. **颜色标记 + OCR 预览 + 用户确认填入（已选）**：保留 OCR 与对齐证据，用户确认页面后才写入。
2. **自动填入**：遇到 OCR 错字或目标页映射错时会直接污染文稿，本阶段不做。
3. **只标色、不提供填入**：更安全但无法完成用户要求的补入流程，本阶段不做。

## 行为细节

1. 扫描点击先在后台读取与当前 endpoint 匹配的 keyring 凭据；没有可用凭据时弹出掩码令牌输入。首次确认后，先将令牌写入系统凭据库，再把新 reference/endpoint 写入 `proofreading.ocr.authentication` 工作区偏好；偏好写入失败时删除刚建的凭据并停止上传。替换凭据时先成功写新值，再切换 reference，最后删除旧值。
2. 提交前记录本次 A/B 内容快照 hash。收到 job ID 后保存恢复记录。若持久化失败，当前窗口继续处理并显示“关闭后无法恢复”的错误，同时允许重试保存；不能丢弃仍可在当前进程处理的任务。
3. 重开后若存在未完成作业，扫描操作显示“继续 OCR”；从 keyring 取出匹配 endpoint 的 token 后按已保存 endpoint 和 job ID 查询。认证或网络失败保留恢复记录，允许重试；认证失败提供替换令牌入口。源 hash 不一致时拒绝将旧结果用于当前文稿，并提示重新扫描。
4. 用户点“停止”只停止本机轮询；PaddleOCR 任务 API 没有由当前集成调用的取消请求，因此保留 job ID 并显示“可继续”，避免把本地停止误报为服务器取消。
5. 完整结果下载并完成对齐后，找出有有效 OCR 文本、但无 B 匹配的 A 页。依据单调页序和相邻 matched 页的 B 范围，寻找唯一的空 B 页候选。重复空页、多个候选或边界不确定时不生成自动填入候选。
6. 缺文颜色显示在 X 页顶部状态标签及右侧页码导航状态上；候选详情列出 A PDF 页码、B 页码、OCR 状态和按块阅读顺序生成的预览文本。确认前不更改 B；确认时要求目标页仍为空、源/B hash 与扫描快照一致，并且有序 B 页范围指纹未变化。
7. 应用后通过校对 controller 的页面替换操作写入文本，保留常规撤销、脏状态与保存行为；候选状态随 B 内容变更清除或重算。

## 验收

- 首次令牌存入操作系统凭据库，workspace/project payload 只保存 opaque reference 和 endpoint，不含令牌；同一 endpoint 后续扫描与恢复从凭据库自动取用。
- 凭据库写入失败时不上传 PDF；认证失败保留 job ID 并允许替换令牌。
- 已提交 job ID 在重新打开项目后恢复轮询；恢复路径不再次调用 Submit。
- 上传尚未返回 job ID 即退出时，UI 如实要求重新提交；服务端错误/认证错误不丢弃已保存 job ID。
- A/B hash 改变时不会应用旧扫描结果；普通 B 编辑不会被 OCR 覆盖。
- 相邻匹配唯一夹定的空 B 页显示缺文色和 OCR 预览；确认后只更新目标页并走常规保存/撤销路径。
- B 页目标不唯一、OCR 无文本或结果 limited/ambiguous 时不自动填入；取消预览不修改文稿。
- 实际界面按仓库 `AGENTS.md` 流程从当前源码目录启动验证；测试通过不得表述成已目视验证。
