# 校对页状态筛选设计

## 目标

工具栏只保留“已校对”和“未校对”两个筛选按钮。它们筛选正在比较的页面；A 原文和 X 校对页始终展示同一组 PDF 页，保持原有页序、滚动和页码同步。

## 方案

使用共享页面索引映射，让 A、X 两个纵向列表按同一个状态筛选结果布局。筛选模式为“全部 / 已校对 / 未校对”：初始显示全部；点击状态按钮切换到对应筛选；再次点击当前筛选恢复全部；点击另一个状态直接切换。

只筛 X 会让原文和校对页错位；只让上一处/下一处跳过其他页不会真正筛掉页面。因此选择让 A 和 X 同步筛选。校对工作台工具栏中原有的“上一处/下一处”装饰项没有操作，页码和 A/X 同步说明也与底部缩略图导航重复，均从工具栏移除。

## 行为约定

- 筛选依据当前页的 `Reviewed` 状态，不以快照是否保存作为判断条件。
- 切换筛选时，若当前页仍匹配则保持当前页；否则选择原 PDF 页序中下一个匹配页，越过末尾时回到第一个匹配页。
- 页面主视图和底部缩略图条的上一页/下一页遵循筛选结果。没有匹配页时，A、X 显示对应的空状态，页导航不可用。
- 底部缩略图仍展示全书和每页状态。点击当前筛选之外的缩略图时清除筛选，再定位到该页。
- 筛选状态只属于当前校对窗口，不写入校对进度；重新打开时显示全部页。
- 从 PDF 页面进入文档工作台时，PDF 快照只作为校对任务的 A 栏原文；工作台只新增 A/X 校对任务标签，不再另开一个普通 PDF 文档会话。

## 范围与约束

不改变校对状态的存储、快照或提交行为，也不改变单页内容编辑。列表内部使用筛选后的行索引，所有页面编辑、状态读取、历史记录和源 PDF 访问继续使用原 PDF 页索引。

## 全部历史页面（设计节点 `sJZ5u`）

全部历史在当前 A/X 校对工作台标签中作为独立整页显示，不再使用旧的右侧抽屉。页面保留顶部应用标签栏，其下提供“返回校对工作台”入口；主体分为左侧页面列表和右侧所选页的 Git 提交时间线。左侧列出确实存在 Git 快照的页，按最近提交时间倒序，并显示页数、最新提交时间和该页提交数；右侧逐条显示该页提交的主题、短哈希、作者/日期、该次提交涉及的全部路径、提交级增删总数与文件数，以及有限的整次提交 diff 摘要。状态标签表示当前页文件在提交中的状态。选择左侧页切换对应时间线；选择某条提交后可将该页恢复为待确认修改。

浮动菜单删除“本页历史”，统一从工作台顶部“全部历史”入口进入。SQLite 仍负责工作进度和已校对状态；此页面展示的逐页版本、作者、时间和文件差异从项目本地 Git 仓库读取。页面加载、切换页面和读取差异都在后台完成；空仓库、加载失败、无选中页和恢复冲突均有明确提示。返回或按 Escape 关闭页面后回到同一校对任务。

实现选择：按 `sJZ5u` 直接重构既有历史路由，不保留抽屉作为第二入口，也不把历史导航到独立应用页面。页面上的“全部页面”筛选控件暂作全页范围标签；历史数据仅包含有 Git 提交的页面，具体页选择由左侧列表完成，不引入设计稿未定义的筛选行为。

## 验收

测试覆盖筛选结果、切换/清除行为、当前页保留或跳转、空结果、缩略图清除筛选，以及 A/X 对相同原 PDF 页的映射和滚动同步。历史页还需覆盖 Git 页面聚合、逐页提交差异统计、整页路由布局、左侧页切换、恢复单页和移除浮动菜单历史入口。
