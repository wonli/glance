# Word 版本历史设计

## 状态

产品方向与本规格对应的决策已获用户批准。版本历史存放在 Glance 本地 SQLite 工作区；自动保存也可产生版本，相同内容去重，自动保存版本限频；恢复前留存当前版本，恢复操作可通过 Word 撤销栈撤销。原有 Native 分阶段实现及 Computer Use 检查已验证版本元数据、恢复、`⌘Z`/`⌘⇧Z` 与退出重启后的历史持久性；Pencil 参考也已核对。2026-10-04 的代码审查补出“恢复前存在未提交正文草稿”边界，现已加入先提交草稿、失败则取消恢复、重建共享文字缓存并强制同步聚焦编辑器的实现和定向回归。后续复审又补上撤销/重做时正文块、共享文字缓存与重置 epoch 的一致更新、跨窗口的恢复失败提示通知，以及共享草稿刷新完成后仅由一个窗口领取和启动恢复；对应竞态检测已通过。最终修复版的这一路径尚未完成 CUA 复验：临时应用启动后 Computer Use 返回 `timeoutReached`。历史面板未改变主页面既有几何；整页 Pen 1:1 对照仍未通过验收，详见中文 TODO 中的视觉差异记录。

## 目标

为已保存的本地 DOCX 提供持久化时间线。用户可查看历史版本，并将某个完整 DOCX 包恢复到当前 Word 会话。版本历史独立于当前进程内的普通撤销/重做历史；关闭标签页或退出 Glance 后，历史仍保存在本机工作区数据库中。

## 范围与用户行为

1. Word“文件”功能区的“版本历史”打开版本列表。列表按时间倒序显示版本时间、来源类型（打开基线、手动保存、自动保存、恢复前保护）和文件大小。
2. 只有有本地保存路径的 DOCX 提供持久化版本历史。未命名文档在首次成功保存前禁用此命令并说明需先保存。加密 DOCX 和非 DOCX 格式不属于本功能范围。
3. 首次打开某个本地路径时创建基线版本。此后打开同一路径时，对当前包做内容去重；若磁盘内容已与历史不同，则记录新的打开基线。重新打开未变化的内容不会重复占用历史空间。
4. 手动保存仅在目标文件成功写入后记录本次实际写入的 DOCX 包。保存失败时不增加版本，并保留原有脏状态和既有保存错误行为。
5. 自动保存成功后也尝试记录本次实际写入的快照；同一路径的自动保存版本最短间隔为 5 分钟。相同内容无论来源和时间间隔如何都只保留一份快照。手动保存不受自动保存限频影响。
6. Save As 到另一个路径后，版本时间线使用目标路径的历史；新目标没有历史时建立基线，已有历史时沿用目标路径时间线。原路径的时间线保留。路径按现有 workspace 的规范化本地路径规则归一化。
7. 恢复前先将当前会话的完整 DOCX 包保存为“恢复前保护”版本。只有该保存成功且选中版本通过校验后才应用恢复。若任一步失败，当前会话内容保持不变。
8. 恢复前先将当前窗口和共享会话里的正文文字草稿全部提交到 DOCX 适配器；任一草稿提交失败时取消恢复，且不写入恢复前保护版本。恢复将选中版本作为一个 Word 文档编辑应用到当前会话，不立即覆盖磁盘文件；会话变为脏状态，用户可撤销一次回到包含这些草稿的恢复前状态，也可重做恢复到所选版本。恢复及撤销/重做后重建共享文字缓存，并强制同步每个窗口的聚焦编辑器。之后的普通保存或自动保存按现有流程写入活动路径并产生相应历史记录。
9. 删除历史条目不提供单独用户操作。每个路径最多保留 50 个版本或 512 MiB，任一限制达到时按最旧时间删除，直至满足限制。快照自身超过单文档字节上限时不记录。

## 数据与架构

### SQLite 持久化

当前工作区 SQLite schema 为 `user_version=4`，由 v3 事务迁移新增版本表；迁移测试覆盖从 `user_version=1`、`2`、`3` 升级。每条记录至少包含：稳定版本 ID、规范化路径键、可读路径、版本来源、UTC 创建时间、DOCX 完整包的 SHA-256、字节长度和完整包 BLOB。对同一路径的内容哈希建立唯一约束，以实现跨手动保存、自动保存、打开基线及恢复前保护的内容去重。列表查询只取元数据；用户选择查看或恢复时再读取对应 BLOB。

插入版本、去重检查和保留策略清理在 SQLite 事务中完成。保留策略按路径统计版本数量和总字节数，并删除最早的记录。不能把版本表写入成功误报为源 DOCX 已成功保存，也不能把源文件保存成功误报为版本已成功记录。

工作区数据库的现有串行写入边界负责版本写入，避免 Gio 帧布局中做归档或数据库 I/O。版本快照不增加新的第三方 Office 运行时；快照读取、写入和恢复均通过现有 DOCX 适配器与工作区 SQLite 完成。

保存 worker 必须在持有适配器写锁时完成文件保存并捕获与其相同 revision 的不可变快照，再将该快照和保存路径交给工作区写入层。不能等 UI 消费保存结果后重新调用 `Snapshot()`：此时文档可能已被后续编辑，历史记录必须对应实际写入的版本。Save As 使用其目标路径作为该保存结果的历史键。

### DOCX 适配器边界

完整快照必须覆盖整个 OOXML ZIP 包，而不只是正文文本或已识别属性，以保留未知 XML、关系、媒体和其他未支持部件。快照序列化和重开仍由 `internal/format/docx` 实现；任何 Office 库类型不越过格式适配器进入 UI、工作区或中立文档模型。

适配器提供一个原子化的“从快照恢复为一次 Word 历史编辑”能力：先验证目标包可解析，再将所有包部件作为一个整体历史条目切换。撤销恢复应回到切换前完整包，重做恢复到所选完整包；不应为每个 XML 部件暴露单独撤销步骤。恢复结束后由 controller 发布新的中立文档快照、脏状态和分页 revision。

### UI 与异步工作

版本列表采用独立于通用表单的轻量历史列表视图。Gio 列表与点击状态保存在稳定 view state 中；快照读取、哈希、DOCX 校验、恢复和 SQLite 写入都在 UI 帧之外运行，并通过现有同步状态发布结果。恢复期间禁用冲突的正文修改和保存入口，显示进度；完成后重新排版并刷新状态栏。恢复前的草稿刷新在 controller/session 层串行执行，不在 Gio layout/frame 中进行；共享 flush 标志为原子状态，排空后待恢复版本由共享会话锁保护并只可领取一次，claim 在恢复 worker 完成后释放，不依赖发起窗口是否仍在处理结果。恢复、撤销和重做在发布共享 revision 前一致更新正文块、文字缓存与重置 epoch；窗口读取时取得同一份投影快照，并在各自窗口的布局循环中更新 Gio 编辑器，确保当前焦点不会阻止显式恢复生效。恢复前草稿提交失败或恢复 worker 报错会在共享会话记录线程安全的通知，唤醒正在显示该文档的窗口，并在各窗口自己的 UI 循环中展示。worker 会在投递仅属于发起窗口的异步结果前写入恢复错误，因此即使发起窗口先关闭，其他活动视图仍能展示失败。

历史列表只展示本地元数据，不自动加载每个版本的 DOCX 包。加载失败、损坏记录和过期记录以可读错误呈现；不能静默跳过后声称恢复成功。

## 错误与一致性

- 打开文档时基线写入失败，不阻止用户读取文档；显示历史暂不可用的提示，不声称已建立基线。
- 源 DOCX 写入成功、SQLite 版本写入失败时，源文件保持已保存状态，UI 明确提示“文件已保存，但历史版本未记录”。普通保存 dirty 状态按文件保存结果处理。
- 自动保存版本限频只影响历史快照，不改变现有 DOCX 自动保存时机或脏状态。
- 恢复前保护版本写入失败、选中 BLOB 哈希错误、包解析失败或恢复 adapter 操作失败时，保持会话原状并报告失败。
- 恢复前任一正文草稿提交失败时，不应用所选快照、不写入恢复前保护版本，并保留未提交草稿供用户继续编辑或修正。
- 如果单个快照超过 512 MiB，不录入历史；恢复前保护快照无法记录时拒绝恢复，避免发生没有退路的替换。
- 写入、恢复和保留清理必须通过事务或临时状态避免半条版本记录或半应用 DOCX。超限清理不可删除正在保护的恢复前快照。
- 路径对应的源文件即使被移动或删除，工作区中已有版本仍保留，直到该路径历史按保留策略清理。

## 数据安全边界

历史完整包 BLOB 与现有 workspace 恢复快照一样以明文存放在本机 SQLite 数据库中；此功能不提供静态加密、安全擦除、云同步或跨设备历史。文件级 DOCX 加密仍属于单独的保护文档能力，未实现前不宣称版本库能保护敏感文档。保留策略只控制应用逻辑可见的历史记录，不承诺底层存储介质上的安全擦除。

## 验收条件

- 同一路径打开和保存产生正确基线与手动版本；相同包哈希不会产生重复记录。
- 自动保存可生成历史版本，但连续自动版本相隔至少 5 分钟；手动保存不受限频影响。
- Save As 后使用目标路径自己的历史，原路径历史可继续查看。
- 关闭或重启后仍能列出历史；未知 DOCX 包部件随完整包保留。
- 恢复前版本先持久化；恢复整包作为一次撤销/重做操作；恢复前保存、读取或解析失败不改变当前文档。
- 有未提交正文草稿时，恢复前快照与单步撤销均包含草稿文字；恢复、撤销和重做后所有窗口（包括仍聚焦的编辑器）显示与 DOCX 适配器一致的正文。
- 任一路径历史不超过 50 条和 512 MiB；清理最旧版本且保留刚写入的必要恢复前版本。
- 历史数据库写失败与源文件保存失败在界面上能区分；不会虚报历史已保存，也不会静默丢 dirty 状态。
- 通过 `go run ./cmd/desktop` 使用纯本地实现；不依赖 LibreOffice 或其他外部 Office 程序。

## 非目标

- 加密 DOCX 的口令、加密/解密和安全保存。
- “审阅 > 限制编辑”一类防误改属性。
- 多设备同步、云版本历史、用户可配置保留策略或单独删除历史版本。
- XLSX、PDF、Markdown 等其他格式的版本历史。
- 自动比对两个版本的文本差异；首版恢复完整文档包。
