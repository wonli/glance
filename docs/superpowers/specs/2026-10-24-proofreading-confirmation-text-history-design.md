# 校对重新确认与正文历史

用户已在会话批准方案：已校对页面改字后橙色显示“已修改，待确认”，按钮改为“确认修改”；确认完成恢复“已校对”。保存期间显示“正在保存”，失败允许重试，继续编辑不得被旧确认结果覆盖。沿用现有确认、IME 与自动草稿保存边界。

历史默认显示每次提交相对父提交的该页正文差异：按 Unicode 字符比较，删除红色删除线、新增绿色、保留上下文并换行。作者、时间、恢复入口保持；完整 Git JSON 差异可通过“原始数据”展开。首次提交视为空正文到当前正文，删除页面相反；元数据变化不能伪造成正文增删。

采用已有模型状态与后台 Git 读取，新增中立正文差异片段，不添加依赖、不改历史数据格式。另一方案是只把 Git JSON 高亮，无法准确展示少量删字；直接比较整段正文则会把细小修改放大，均不采用。

所有验证在当前授权目录，复用现有缓存；不创建 worktree，不改用户历史文件。针对状态、中文删字、重复字符、多处编辑、长文本、初次与无正文变化，以及 1x/2x 像素进行检查。

后续用户修订：历史默认仅展示发生增删的逻辑行，同一行保留逐字高亮，未变化的整页内容省略；完整数据仍可展开。浮动菜单删除额外待确认说明行，仅改变原“已校对”按钮文字与填色；菜单75dp高，改为右键打开，左键只用于编辑与选取。
