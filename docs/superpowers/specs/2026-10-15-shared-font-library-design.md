# Word / Excel 共享字体库设计

日期：2026-10-15。状态：设计草案，待审阅；尚未实现。

## 目标与已确认边界

用户希望读取本机全部字体，让 Word、Excel 复用合理的字体选择组件，并支持网络下载字体。用户已确认：下载字体只供 Glance 使用。

成功标准是字体可被发现、搜索、预览、应用，并在文档绘制和 PDF 导出中实际使用。仅写入字体名称不算完成。下载文件存入 Glance 持久数据目录，不安装到系统；字体索引和预览属于可重建缓存。

## 现状依据

- Word 的 `internal/desktopui/word_text_formatting.go` 使用手填字体名对话框。
- Excel 的 `office_ribbon_menu_definitions.go` 固定列出四种字体，`spreadsheet_formatting.go` 通过输入框处理其他字体。
- `internal/wordfont` 已有系统字体扫描、字体匹配、字形加载与缓存，使用当前锁定的 go-text 依赖。其字体列表当前只加载一次，不能直接承载动态下载。
- Excel 在 `grid_paint.go` 通过 Gio theme shaper 绘制，和 Word 自有排版使用不同入口。
- Word、Excel PDF 导出各自持有通过 `wordfont.NewSystem` 创建的长期 shaper。只更新 UI 下拉列表不会让这些入口自动识别新字体。

## 方案选择

1. **推荐：共享字体目录、解析服务和下载服务，渲染器分别适配。** 保留现有 Word 排版和 Excel 绘制方式，共享字体来源、身份、别名、匹配规则与目录版本。
2. 只共享下拉列表：改动较少，但下载字体可能出现在列表却无法绘制或导出，不满足目标。
3. 同时统一 Word、Excel 整套文字排版引擎：范围远超字体管理，增加分页与表格布局回归风险，不作为本次工作。

## 模块和依赖方向

```text
Word / Excel 字体入口
        ↓
共享 FontPicker（desktopui，稳定交互状态）
        ↓
应用层 FontService（目录快照、任务、事件）
        ├── fontcatalog（扫描、元数据、搜索、匹配）
        └── fontdownload（字体源、下载、私有文件库）

字体目录快照 → wordfont / Gio 接入层 → 文档绘制与 PDF 导出
```

- `internal/fontcatalog` 不依赖 Gio、Word 模型或 Office 库。内部字体解析类型不出包；对外输出中性 DTO 和只读字体资源句柄。
- `internal/fontdownload` 管理网络和私有文件，依赖目录提供的解析/注册边界，不直接修改 UI 或文档。
- 应用层持有进程内共享服务，多个窗口复用。后台任务有明确取消与关闭生命周期，不能依附某个临时弹层或遗留无管理 goroutine。
- `internal/wordfont` 继续负责 Word shaping，但字体来源与匹配通用规则下沉到共享服务；Word 特有的脚本字体槽、兼容字体度量仍留在 Word 层。
- FontPicker 仅发送字体选择意图；Word 和 Excel 各自通过既有命令路径修改中性文档格式。

## 目录、身份与扫描

对外的 Family 条目包含稳定 ID、规范家族名、本地化名称/别名、字面列表、来源、可用状态和能力信息。Face 条目包含字重、斜体、文件内容身份和集合中的 face index。UI 不接触第三方 footprint 或 face 对象。

系统扫描后台执行，覆盖平台字体发现机制报告的字体；单个损坏或无权读取的文件产生诊断，不让整个目录失败。平台无法枚举的受保护字体不能声称可用。首次可展示缓存目录，异步核验后发布新版本；用户可手动刷新，重启时重新核验。第一版不增加全目录实时文件监控。

中文名和英文名按同一字体元数据归并，不按文件名猜测。不同字重归同一家族；同名但内容不同的系统/私有字体保留各自来源，不能静默覆盖。同一具体字面优先选择精确匹配，内容冲突时采用稳定顺序：已有绑定优先，未绑定时系统来源优先，私有来源可明确选择。

目录版本单调递增。扫描、注册、刷新成功后发布不可变快照；搜索、预览、布局结果携带版本，丢弃迟到结果。完整字体数据和字形不随目录全量预载，按需加载并限制缓存容量。

## 选择器交互

Word 与 Excel 的字体入口统一打开锚定 Ribbon 的 FontPicker，替换手填主流程和 Excel 固定名单。可保留手填字体名的高级入口，允许保存当前机器没有的字体，同时明确显示不可用状态。

- 顶部搜索框支持中文名、英文名和已知别名，搜索不改写文档；输入中文时保持 IME 组合状态。
- 默认提供当前字体、最近使用、本机与已下载字体；文档字体入口展示当前文档引用的字体及缺失状态。文档字体汇总在后台基于修订快照计算，不能为打开列表同步扫描整本工作簿。
- 在线字体作为独立入口，只有打开该入口或主动刷新时才请求网络，不能随用户输入上传文档文字或本机字体清单。
- 每行展示本地化名称、来源/状态和固定中英文样例。名称使用稳定的 UI 字体，样例按需使用该字体；未下载字体不伪造真实字体预览。
- 列表虚拟化；Editor、List、Clickable 保持稳定身份，列表显式指定纵轴。浮层位于根级 overlay，处理 viewport 限界、滚动锚点、外部点击、Escape、方向键和 Enter。
- 选择本机可用字体后发送一次应用意图。打开时捕获文档/session、选区及修订身份；关闭、切换文档或选区失效后，不再向变化后的目标提交。
- 下载操作只负责让字体可用。下载成功后显示“应用”，由用户再次选择后应用，避免耗时下载结束时改写旧选区。
- 取消或选择当前相同字体不创建文档修改；最近使用只在字体成功应用后更新。

## 私有字体持久化与在线下载

字体正文保存到 Glance 持久数据目录的 `fonts/objects/<sha256>`，索引记录来源、版本、家族、字面、授权文本与校验信息；临时下载放在同文件系统的暂存目录，验证成功后原子发布。索引和扫描缓存分别存储，清除缓存不删除下载字体。重启后可离线发现私有字体。

在线来源通过 Provider 接口提供可列举的版本化清单和下载资源描述。第一版使用随应用发布、固定版本且逐项验证的开放字体清单，应用可直接下载清单中的官方 HTTPS 资源；不提供任意 URL 输入或网页抓取。清单条目必须包含具体来源 URL、版本、大小上限、SHA-256、授权文本及支持能力。首批实际条目在实现阶段逐一核验后纳入仓库，缺乏这些证据的资源不发布。

第一版在线清单仅发布经 Word、Gio、PDF 三条链路验证的静态 TTF 字体资源。系统目录继续报告发现的其他格式，但按渲染和导出能力显示限制；不将“能够扫描”视作格式兼容证据。其他 OTF、集合、可变字体和 Web 字体下载支持须单独验证后扩展，第一版不添加格式转换器。

下载状态为可下载、下载中、验证中、已就绪、失败；进度和错误可见，支持取消及重试。相同资源复用一个后台下载，限制并发、响应大小、时间与重定向目标。校验散列、字体实际解析结果、声明身份及授权记录后才注册。下载失败不发布半成品；崩溃遗留暂存文件在启动时清理。网络不可用不影响本机字体。

此处的授权记录用于资源管理，PDF 输出继续遵守既有嵌入检查。应用内可显示不等于可嵌入 PDF，不能绕过当前导出错误。

## 渲染更新与文档安全

共享解析结果需要区分请求字体名、解析到的字体身份、替代原因和覆盖能力。中英文字段保持文档原始语义，不将平台替代字体自动写回 DOCX/XLSX。

- Word shaper 从指定目录快照获取字体资源，保留当前脚本选择和 fallback 行为；每个排版任务固定一个快照。
- Gio 接入层向 Excel 内容和字体样例提供系统与私有字面。新增私有字体时在 UI 安全边界更新内容 shaper，避免修改正在使用的对象。主页与设置页的主题字体不随文档选择改变。
- Word 布局键、Excel 文本测量/绘制缓存及预览键包含目录版本，发布后重新计算受影响内容。字体更新不自动改变单元格存储的行高、列宽或文档 dirty 状态。
- PDF/打印任务固定字体目录版本和资源租约，保证一次任务使用同一组字面；新任务看到新目录。后台导出不得继续无限使用只识别旧系统字体的全局单例。
- DOCX/XLSX 保存规范字体家族名，不保存私有绝对路径或下载地址，不自动嵌入字体。同名不同版本的精确绑定仅能作为本机工作区元数据；跨机器重开仍可能替代，不能承诺文件携带字体或跨机器像素一致。
- 第一版支持下载和刷新，不提供运行期间删除已下载字体的交互；避免引入在用资源释放问题。对象租约接口保留后续删除的扩展空间。

## 验证要求

使用测试字体、临时目录、内存 Provider 与本地 HTTP 测试服务，不读取用户私有字体数据作为断言，不依赖公网。

1. 目录：中文/英文别名、字重归并、集合 face 身份、同名冲突、损坏文件、刷新、缓存失效和私有目录重启恢复。
2. 下载：成功、取消、失败重试、并发去重、大小/散列/字体身份校验失败、原子发布和崩溃暂存恢复。
3. 交互：Word/Excel 共用列表和搜索、中文 IME、键盘操作、滚动与浮层限界、无操作提交、异步完成后的选区/session 失效保护。
4. 实际渲染：同一下载字体在 Word 和 Excel 的中英文样例中确实采用目标字面；通过资源身份和实际像素两种证据验证，不只断言字体名。
5. 更新：先以缺失字体排版，再注册该字体，确认目录版本使绘制、文字测量、Word 分页缓存失效；刷新不修改文档数据。
6. 导出和保存：Word/Excel PDF 使用所选字体资源，嵌入限制错误仍可见；DOCX/XLSX 保存重开后字体名称和代表性未修改内容保留。
7. 并发：下载/刷新与排版、PDF 输出同时发生时，单次任务资源版本一致；执行适用的 race 检查。
8. 视觉：1x/2x 真实 GPU 渲染和真实窗口交互；GPU 不可用导致的 SKIP 明确记录为未验证。

实现时同步更新 `docs/architecture.md`、`docs/office-support.md` 及适用的兼容性证据，不扩大字体支持声明到尚未验证的格式。

## 交付顺序

1. 共享目录、私有资源存储、渲染接入和目录版本失效机制。
2. Word/Excel 统一选择器，本机字体可搜索、预览和应用。
3. Provider、首批经核验的在线资源、下载交互与重启离线复用。
4. 保存/导出、并发及 1x/2x 交互渲染验证，更新兼容性文档。

上述阶段是同一目标的实施顺序，不能在完成下拉列表后将网络字体或实际渲染接入标记为已完成。
