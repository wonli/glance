# 校对列表完整稿导出设计

## 意图

在校对列表的每个任务行增加“导出”，让用户保存一份完整、按 PDF 页序排列的稿件。导出内容由当前有效的已确认页和导入任务时的 B 原稿页组合而成。Git 用于保留确认历史，不作为导出资格的硬门槛。

## 目标

- 用户从任务行点击“导出”，选择保存路径后获得完整文档，不因 Git 未安装、快照失败或尚未提交而缺页。
- 页序固定使用 PDF 页 ID 的升序，不按 Git 提交时间、最近操作时间或当前浏览顺序排列。
- 当前已确认且确认后未修改的页面使用已确认内容。若没有对应 Git 快照，但本地恢复模型可证明内容仍与确认时一致，则使用本地当前内容。
- 尚未确认的页面使用任务保留的 B 原始输入内容；不得使用这些页当前未确认的编辑作为原文替代。
- 输出扩展名与导入的 B 原稿一致：`.md`、`.markdown` 或 `.txt`。首版不导出 `.doc` / `.docx`。
- 导出另存为新文件，不改写原 B 原稿、校对副本、SQLite 进度或 Git 历史。

## 非目标

- 不导出 PDF，也不接入 A PDF 的文字提取或 OCR。
- 不导出 Word 文件，不承诺保留 Word 样式、图片、表格或其他 Office 内容。
- 不创建 Git 快照、不推送、不修改页面校对状态。
- 不增加页选择器、格式选择器或额外的导出范围配置。

## 用户流程

1. 校对列表任务行提供“导出”操作，与“继续校对”和“删除”并列。
2. 对支持的 B 原稿类型，点击后打开原生保存位置选择器；默认文件名基于 B 原稿文件名，扩展名沿用原稿。取消选择不产生文件或状态变化。
3. 选择路径后，在受管理的后台任务中读取任务恢复数据、原 B 原稿及可用的确认快照，按 PDF 页序组装并写入目标文件。Gio 布局帧不执行文件读取、解析、组装或写入。
4. 成功或失败通过现有工作台状态/通知反馈。Git 不可用、某页没有 Git 快照本身不阻止导出。
5. 对 `.doc` / `.docx` 任务不执行导出，并显示当前不支持该原稿格式的明确提示。

## 内容组装

- 任务页按 PDF 页 ID 从小到大处理，输出完整页序，不丢弃未确认页。
- 若某页当前已确认，且当前内容哈希与保存的确认哈希相同，则导出这份确认内容。优先读取内容哈希匹配的 Git 页快照；Git 不可用或快照缺失时，从恢复模型读取，并再次校验确认哈希。
- 若页面确认后发生编辑、确认状态仍在处理中，或恢复数据不能证明当前内容等于确认内容，该页不能把新编辑冒充为确认稿。导出应停止并说明页码及原因，提示先完成确认/保存后重试；不得静默回退为原文或静默输出未确认内容。
- 未确认页使用项目内保留的原始 B 文本在该 PDF 页对应的内容。A 栏 PDF 仅作视觉参考，不从中抽取文本。
- Markdown / 纯文本输出按原始字符顺序连接页内容，不加入人为页码、Git 信息、分隔线或格式标记；只保留内容本身已有的换行。写出为 UTF-8，换行统一为 LF。
- 原始 B 输入和已确认页快照均不可变读取。导出不改变打开中的工作模型或编辑草稿。

## 方案与取舍

1. **仅从 Git 快照导出已提交页。** 实现最直接，但缺 Git 或缺少快照时会漏页，产生不完整稿件；与“完整稿”目标冲突，排除。
2. **混合组装完整稿（选定）。** 已确认页使用能验证为当前确认内容的版本，未确认页使用 B 原稿，Git 只提供可用的确认快照。内容始终完整，且不会把未确认编辑混入输出；需确保原始 B 内容仍能准确映射到导入时的 PDF 页序。
3. **始终导出当前工作副本。** 不会因 Git 状态缺页，但会把确认后的未确认修改写进成品，失去“已校对”边界；排除。

对格式，用户选择按 B 原稿扩展名导出。Markdown 和纯文本可以从现有逐页文本流组装；Word 导入目前会展平结构，不能安全承诺同格式往返，因此首版不处理 Word。

## 约束与兼容

- 保持 `internal/desktopui` 仅通过应用工作区数据和现有文档边界读取任务；Git 命令仍封装在 `internal/proofhistory`。
- 页面导出状态以持久化确认标记、内容哈希和当前恢复模型共同校验。单有 `Reviewed` 布尔值不证明内容是已确认版本。
- 每个任务保留的 `SourceB` 是导入时复制的原稿，`SourceA` 是原 PDF。必须提供稳定的“原始 B 文本到 PDF 页”的对应，以便中间页完成确认后用原稿内容补齐其他页。新建任务应保留必要的原始页归属证据；既有任务应从仍保留在模型里的原文字符身份和页归属恢复边界，并用原稿、PDF 几何和初始布局规则补足已删除字符留下的空档。字符身份顺序冲突或完全没有原文字符身份时，停止并解释，不导出错页内容。
- 保存失败不得损坏已有目标文件。目标文件应先完整写入同目录临时文件，验证成功后再按保存选择器的替换确认语义发布。
- 中英文新增文案应进入现有 i18n 资源。

## 留给实现者

- 复用仓库现有原生保存位置选择器；如不存在合适的 Save Panel API，选择最符合当前跨平台文件选择器的实现。
- 设计新任务原始页归属证据的最小持久化形态，并为已经存在的任务实现可验证的恢复路径。
- 对 Markdown / TXT 使用现有内容流和分页模型，不尝试往返重建 Word 富文本结构。
- 增加针对性测试，覆盖 6→500→7 的页序、已确认页有/无 Git 快照、未确认页原文补齐、确认后修改阻断、取消保存对话框、目标写入失败及已存在目标文件的安全处理。
