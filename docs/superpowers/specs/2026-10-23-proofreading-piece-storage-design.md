# 校对盒子与共享文本片段

用户要求本次采用更好的数据结构，避免大稿件性能问题后续返工；已选择盒子数组与共享文本片段方向。

## 选择

盒子链表不适合按页随机访问；全书单一 Runs 数组会令每次滚动复制历史、扫描和验证整稿。采用固定页索引数组，每盒持有不可变的平衡文本片段树。字符串及字符身份共享，片段缓存字符长度；拆分仅在边界切分 UTF-8 子串。无需新增依赖。

数组保留固定 PageID 和页状态。整盒补位移动片段树引用，不遍历字符。每次操作历史只保存受影响盒子的前后根及状态，局部编辑只记录局部页；补位记录移动的盒子引用。普通收退为局部树操作，补位 O(受影响盒数)，不随全文字符数或每页片段数增长。相比给页序列再加持久化树，这一结构更直接，且界面本身仍需发布受影响的盒子；用 892 页多片段基准验证实际开销。

## 保持的行为

- 字符稳定 ID、顺序、Typed 保护、已校验屏障和原 B 不变。
- 空盒补位与收取同一步撤销，普通逐字收退仍逐步撤销。
- 第 2 版 Snapshot 只作为导入、后台快照、持久化边界，保存格式兼容。
- 旧锁定／自动 Reflow 接口通过隔离的快照转换桥兼容；当前编辑、收退和分页直接使用片段树，不维护第二份可变正文。
- UI 热路径使用当前页和邻页访问，不为每一个字符调整展开整书 Snapshot。

## 验证

先记录现有 892 页、每页八片段基准；再覆盖多片段补位、原始字符 ID、撤销后再编辑、快照隔离、中文和 emoji 边界、保存重开及跨帧排版。报告技术基准与实际界面验证的不同范围。
