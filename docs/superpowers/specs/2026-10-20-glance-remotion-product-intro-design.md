# Glance-go Remotion 产品介绍片设计

## 目标

制作一支约 30 秒的 9:16 抖音产品介绍片，面向对桌面办公、独立产品开发和 Agent 工作流感兴趣的观众。影片以“老王持续打磨 Glance-go”的开发者自述建立个人印象，并用真实产品画面说明用途与优点。创作者本人不出镜；使用自然克制的合成普通话旁白、中文字幕、科技感配乐和轻量音效，不克隆真人声音。

本片重点传达：

1. Glance-go 是轻量的原生桌面办公工具，使用 Go 与 Gio 构建桌面界面。
2. macOS 便携包体积小；Windows 使用单文件 EXE。包体信息按平台区分展示。
3. 应用从启动开始进入桌面工作区；用真实启动画面表现体验，不宣称未经测量的启动秒数。
4. Agent 是产品的一等使用者：桌面 UI 与 Agent 共用同一套文档能力，Agent 可以围绕当前文档协作。
5. 通过 Word、Excel、PowerPoint、PDF、Markdown、JSON 等真实界面证明产品用途。
6. 老王会持续打磨并记录 Glance-go 的开发过程。

影片不把包体大小、MCP、文档格式和代码指标全部堆进旁白。数据作为短字幕或平台卡片呈现，旁白保持自然、简短的开发者口吻。

## 叙事与文案

主线采用“开发者自述 + 产品演示”。文案应像老王在分享自己正在做的产品，不使用企业发布会口吻。保留持续打磨和公开记录的个人表达，不复用此前的功能汇报式文案。

旁白初稿：

> 我是老王，正在打磨 Glance-go，一款轻量的原生桌面办公工具。
> macOS 便携包二十多兆；Windows 版是单文件 EXE。启动快，打开就回到工作区。
> 常用工作文件，在这里打开就能接着处理。
> Agent 也能直接参与当前文档的工作，和桌面共用同一套文档能力。
> 这是一个值得长期打磨的产品。我会把每一步记录下来，欢迎关注老王。

这段文案约 30 秒，仍可在剪辑时按真实旁白节奏微调。包体数字字幕使用当前构建产物的实测大小：macOS ARM64 便携 ZIP 约 24 MB、Intel 便携 ZIP 约 26 MB；Windows 单文件 EXE 约 79 MB。画面标清操作系统和包类型，避免让人误以为所有平台都有相同格式或大小。启动速度没有基准数据，影片以真实启动录屏展示，不叠加具体秒数。

## 画面与节奏

成片为 1080×1920、30 fps、约 30 秒。视觉基调为留白式科技产品展示：深海军蓝背景、冷蓝高光、克制的网格和光束。完整应用窗口是主视觉，尺寸约占画面可用区域的 70%–75%；标题、字幕和数据放在上下安全区。进入细节时只推近应用内容，不裁掉主展示镜头的完整窗口外壳。

| 时间 | 画面 | 旁白/屏显重点 |
|---|---|---|
| 0–4 秒 | Glance 图标与完整应用窗口显现；干净的冷蓝光线勾出窗口轮廓。 | “我是老王，正在打磨 Glance-go。”屏显“轻量原生桌面办公”。 |
| 4–9 秒 | 平台包体卡片按平台依次入场，随后真实启动录屏转为工作区。 | macOS ARM64 24 MB、Intel 26 MB；Windows 单文件 EXE 79 MB。字幕使用“便携 ZIP”与“EXE”准确标注。 |
| 9–15 秒 | 应用窗口保持完整；文档、表格、演示、PDF、Markdown、JSON 以短卡片快速切换，随后推近一个代表性编辑画面。 | “常用文件都能在这里继续处理。”小型技术标记为“Go + Gio 原生桌面”。 |
| 15–23 秒 | 展示当前文档与 Agent 的协作画面；用一张简洁的共享能力连接图将桌面界面和 Agent 接到同一文档运行时。 | “Agent 也是一等公民，和桌面共用同一套文档能力。”屏显“围绕当前文档协作”。 |
| 23–30 秒 | 快切回到完整窗口，收束至品牌图标和老王的个人 CTA。 | “我会继续把 Glance-go 打磨好，也把每一步记录下来。欢迎关注老王。” |

镜头运动使用短促的推近、平移和横甩转场，方向随镜头内容变化。闪光和拖尾只强调接点，避免持续盖住产品 UI。字幕使用高对比大字号，确保竖屏预览中可读且不挡关键控件。

## 素材与事实边界

- 优先使用参考对话中已有的真实录屏与截图：`/Users/mima1234/Desktop/glance/录屏2026-10-20 20.17.56.mov`、`1.png`、`2.png`。品牌图标使用 `internal/desktopui/assets/brand/glance-dock-icon.svg`。
- 录屏包含本机路径或文件名时，应避开、遮挡或用安全演示文件重录；不要把本机路径、真实业务文档或凭据放入成片。
- 包体数字以当前 `dist` 文件为来源。已检查到 ARM64 ZIP、Intel ZIP、Windows EXE 大小分别约为 24 MB、26 MB、79 MB；最终渲染前再检查一次产物是否已变化。
- 项目采用 Go/Gio 桌面界面。宣传画面写“Go + Gio 原生桌面”，不把 Remotion 的 React/Node 制作工程误写成 Glance-go 的产品技术栈。
- 桌面应用、内置 Agent 和 MCP 共享应用文档运行时与能力目录。旁白限定为“围绕当前文档协作”或“共用文档能力”，不暗示 Agent 可以无约束地修改所有格式。
- JSON 性能数据（100 MiB、约 409 万节点、一次优化解析 464 ms）可作为备用证据镜头；是否采用由最终节奏决定，不能与包体信息同时挤满一个画面。

## 工程组织与输出

Remotion 工程放在仓库现有空目录 `my-video/`，自带 `package.json`、锁文件、源组件和媒体目录。它与 Go 产品构建隔离，不向 Glance-go 增加 JavaScript 或 Web 运行时依赖。只复制最终使用的媒体素材；渲染产物写入 `my-video/out/glance-go-intro-vertical.mp4`，并在该工程内忽略输出目录。

第一版只制作一个竖屏主版本，不做横屏改编、多个语言版本或可编辑的网页播放器。渲染成 H.264 MP4，附普通话旁白、低音量科技感器乐和克制的转场音效；不克隆任何真人声音。

## 方案比较

1. **使用独立 `my-video/` Remotion 工程（推荐）**：视频依赖、组件和素材均与 Go 产品隔离；便于复现、修改和重新渲染，且不会改变产品技术栈。
2. **将 Remotion 包放在仓库根目录**：路径更短，但会把 Node 工具链混入 Go 应用根目录，增加无关依赖和构建入口。
3. **继续只编辑 ChatCut 时间线**：复用已有剪辑素材和效果更快，但无法满足本次使用 Remotion 源码制作的目标，也较难以代码复现精确动效。

选择方案 1。

## 验收方式与风险

- 实际渲染 MP4 后检查开场、包体、格式切换、Agent 镜头、结尾和全部转场接点；检查字幕安全区、完整产品外壳、动态元素遮挡与音乐/旁白响度。
- 通过完整播放确认叙事节奏和声音同步；从首尾及关键转场抽帧，检查竖屏上的实际字号、UI 可读性和裁切。
- 检查最终媒体中没有本机路径、敏感文件名、凭据或未授权的业务数据。
- 包体可能随当前构建产物变化；若最终大小不同，更新旁白/字幕后再渲染。
- “启动快”目前没有可引用的启动时延基准，因此只展示真实启动过程，不声称具体速度。
- 现有录屏是否适合直接使用，以媒体检查为准；如画面暴露路径或敏感内容，需遮挡或补录安全演示素材。

## 范围外

- 修改 Glance-go 产品代码或构建系统。
- 将 Remotion 依赖加入 Go 应用运行时。
- 导出横屏、英文或其他平台版本。
- 未经单独确认发布到抖音或其他外部平台。
