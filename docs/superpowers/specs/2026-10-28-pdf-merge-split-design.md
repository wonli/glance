# PDF 合并拆分小工具设计

## 意图

在 Glance「小工具」页增加 `Bv0wm` 所示的 PDF 合并拆分入口。入口打开独立的工作台页面，用户可以合并多份 PDF，也可以从一份 PDF 按页码范围或逐页拆分并提取页面。工作流留在小工具中，不打开文档编辑器，也不修改源 PDF。

输出写入用户选择的本地文件夹，不提供下载流程。两种模式都属于本次完整交付范围。

## 设计依据与现状

- Ink `Bv0wm`：PDF 合并拆分工具卡片，点击进入工作台。
- Ink `pmPg28a`：合并模式，支持添加多份 PDF、拖动调整顺序、设置输出文件名和查看页数/文件大小汇总。
- Ink `sp28_000`：拆分模式，支持选择一份 PDF、按多个页码范围输出或逐页拆分、设置输出文件名前缀和查看结果数量。
- 当前小工具页在 `internal/desktopui/home_tools.go` 注册并绘制工具卡片；PDF 工作区由 `internal/format/pdfdoc` 管理。当前实现没有 PDF 合并拆分工作台或对应文件处理入口。
- 项目已固定 `github.com/SalvioniDigitalSolutions/gopdf`。该版本带有 PDF 合并和抽取页面能力，现有依赖不需替换。

## 目标

- 在小工具页显示 PDF 合并拆分卡片；进入后提供合并/拆分两种模式及返回小工具页的操作。
- 合并模式能添加至少两份 PDF、删除单项/清空列表、拖动排序，并按列表顺序生成一个 PDF。
- 拆分模式能选择一份 PDF，解析页码范围并逐段生成多个 PDF，或按页生成单页 PDF。
- 显示输入文件名、页数、大小；拆分预览显示将生成的文件数；合并概览显示总页数和输入文件大小合计。
- 两种模式各自保留当前输入和参数；切换模式不清除另一模式的数据。
- PDF 读取和生成都在 Gio 帧/布局之外运行；操作状态、进度、成功和错误通过同步状态返回 UI。
- 通过系统文件夹选择器指定输出目录。合并生成一个按用户输入命名的 PDF；拆分文件使用前缀和两位序号，例如 `项目资料汇总-01.pdf`。
- 源文件保持不变。发现目标文件名已存在时停止并给出可操作的错误，不覆盖已有文件。

## 非目标与边界

- 不在本次增加 PDF 文档编辑、拼页、裁页、压缩、加密、OCR 或在线处理。
- 不写入当前活动 PDF 文档的历史、撤销栈或工作区会话；本工具生成新的独立文件。
- 不增加 MCP/Agent 命令，也不自动打开输出文件。
- 输入文件只接受本地 PDF。加密或损坏到当前解析器不能安全读取的 PDF 应明确报错。
- 该版本以页面可见内容为交付边界。页面导入可保留页面绘制内容和外部网址链接；内部链接与其他批注不保留。签名不能作为有效签名延续到新生成的文件。界面帮助或工具说明应明确这些限制。

## 拆分规则

- 页码从 1 开始，范围两端都包含。支持逗号分隔的页码和升序范围，例如 `1-12, 18, 23-48`；允许数字间空格。
- 空输入、非正整数、逆序范围、超出文档页数的页码，以及重复/重叠页码均显示输入错误，不开始处理。
- 每个逗号项生成一个 PDF，并按输入顺序保留该项内页码顺序。单个页码项也生成一个文件。
- 逐页模式为源 PDF 的每一页生成独立文件。输出序号从 `01` 开始，按页码/范围顺序递增。

## 交互与输出行为

- 入口卡片和工作台延续 Ink 的名称、图标、中文说明、浅色面板与橘色主操作按钮。
- 工作台中的切换控件控制当前视图。合并与拆分使用相互独立的输入列表和草稿参数。
- 合并允许重复添加同一路径；每一行拥有独立移除状态。拖动排序只影响合并顺序。
- 使用本地文件选择器添加 PDF；合并可逐次添加文件。若桌面拖放能力已由当前 UI 层支持，可同时开放文件拖入；否则首版只提供选择文件按钮。
- 开始操作前选择输出目录；目录选择取消时返回工作台，不产生文件。输出文件名只接受安全的文件名部分，不接受目录分隔符。
- 先生成并重开校验临时输出，再提交到目标目录。单文件写入采用原子提交并拒绝覆盖。多文件输出逐一提交；若提交中遇到文件系统错误，保留已成功文件并列明成功/失败文件，不隐藏部分成功。
- 合并总大小是源文件字节数之和，作为汇总值显示，不承诺等于重新序列化后的输出大小。
- 处理期间显示进度或明确的忙碌状态，禁用会改变输入集合和模式的操作；允许取消尚未提交的工作。错误提示保留源文件名与失败阶段，避免只显示泛化错误。

## 架构与实现边界

- 在 `internal/desktopui` 的小工具目录和页面状态中接入卡片与工作台；默认实现为 Glance 主窗口内的独立工具页面，返回动作回到小工具目录。
- UI 只持有中立状态：路径、展示名、页数、大小、范围草稿、输出前缀/名称、目标目录、操作状态和结果。Gio 控件保存在稳定状态中。
- 新增窄的应用层意图/服务接口，将合并/拆分请求送到 `internal/format/pdfdoc`。gopdf 的 Reader、Document 等第三方类型只留在格式适配层。
- 后台操作复用项目的上下文取消、错误回传与文件原子写入模式。每份输出验证可重新打开且页数等于预期；临时文件在失败或取消时清理。
- 需要确认现有平台的 PDF 文件选择是否支持多选。首版可通过重复单文件选择满足合并；如采用多选 API，需在现有 darwin、Windows、other 平台实现上保持行为一致。
- 具体服务方法签名、进度粒度与资源上限由实现者根据当前 runtime 结构决定，并记录测量依据；不在 UI 帧中读入 PDF 或构造输出。

## 实现路线

### 路线 A：复用已固定的 gopdf 页面导入

使用当前依赖的合并/抽页能力，将 PDF 输出写入临时文件，重新打开并核对页数后再安全提交。它支持本设计的合并、页码范围拆分和逐页拆分，避免增加依赖。代价是保真范围限于上文明确的边界。

### 路线 B：先实现或引入结构保真页面树复制

先验证当前 PDF 库或替代库是否能保留内部链接、批注、表单、文档级目录等结构，再按验证结果实现。它减少部分元数据丢失，但需要独立的兼容性评估、跨平台检查和更广的保存/重开样本，工期与失败风险明显增加。

### 选择

采用路线 A。用户确认优先保留页面可见内容并接受内部链接和非网址批注丢失；现有依赖已被项目固定，能满足两个模式的核心页面处理能力。依赖的兼容边界在工具说明中公开，不为本次功能更换 PDF 引擎。

## 验收标准

- 小工具页能看到并打开 PDF 合并拆分工具；返回能回到小工具页，不进入或改变 PDF 编辑器会话。
- 合并至少两份 PDF 后，输出页序与输入列表一致；移动顺序、移除、清空及重复输入均正确处理。
- 按范围拆分覆盖多段范围、单页项、空值、非法字符、逆序、越界和重叠输入；逐页模式输出数量与源页数一致。
- 每份输出都能重新打开，页数和预期一致；输入源文件字节不被改写，已有目标文件不会被覆盖。
- 选择输出目录取消、解析失败、生成中取消、临时写入失败及目标目录不可写时，界面给出清楚结果且临时产物清理。
- UI 在 PDF 读取/生成时仍保持响应；处理中输入和模式状态不会与迟到的后台结果串线。
- 页面丢失批注/内部链接的限制有面向用户的说明；界面中英文文案可用。

## 留给实现者的决定

- 在现有输入文件选择器上增加多选，还是首版按单文件重复添加；以跨平台一致性和代码边界作决定。
- 输出临时文件如何在多文件批次中分阶段提交与报告部分成功；需复用现有 `fileutil` 保障，且不覆盖源文件或已有结果。
- 根据真实样本确定合理的页数/文件大小/输出文件数资源限制。不得在没有依据时硬编码低容量上限。

## 风险

- 页面内容被重新封装到新 PDF；外部阅读器对字体、透明度、特殊 XObject、表单外观和复杂资源的呈现可能与输入有差异。应以选定兼容性边界和可重开/代表性视觉样本验证，不声称全面 PDF 标准兼容。
- 逐页拆分会产生大量文件，需显示结果数量并保持可取消；多文件落盘不是跨文件系统事务，部分提交必须透明报告。
- PDF 解析属于高资源输入路径；后台执行、取消、临时文件清理和有证据的资源预算是交付的一部分。
