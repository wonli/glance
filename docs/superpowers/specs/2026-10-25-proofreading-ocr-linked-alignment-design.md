# 校对 OCR 首尾对齐与 A/B 联动设计

状态：用户已批准（2026-10-25）

## 意图

校对工作台的 AI 扫描目前能把每页 PDF 的 OCR 文字在 B 稿全文中检索并计算有序候选，但 PDF 上的框只表示 OCR 版面块，用户看不到候选对应到 B 稿的哪一段，也看不到整本匹配从何处开始、到何处结束。此设计把已有定位证据呈现为可检查的 A/B 对应，并在真正进行匹配时显示跟随进度的扫描动画。

首尾对齐指自动找到最早、最晚的可靠对应锚点，并沿 A 页序显示中间各页的对应状态与页间切点证据。它不假定 PDF 第 1 页必然对应 B 开头，也不把 B 字符范围误说成已验证的精确页界。

## 目标

- 整本 OCR 完成后，将每页 OCR 证据对应到 B 当前工作稿的字符范围；使用现有跨页单调路径，暴露最早和最晚的可定位页面及两者之间的页状态。
- 显示现有 `BoundaryAfter` 的 `point`、`range` 或 `unresolved` 结果；不得将不确定切点自动变成分页。
- 匹配进行时按算法真实处理到的 A 页更新页码进度，并在该页 OCR 区域显示扫描动画；进度不伪装成字符级处理，也不在所有结果完成前宣称已配对。
- 完成后，用户可从 A 页 OCR 块查看对应的 B 文本范围。可信定位使用明确的匹配样式；有竞争候选的页面显示待确认状态，不以最佳候选冒充确定结果。
- 将 B 的证据范围投影到 X 稿件页并高亮；保留原有 A/X 联动滚动，进入比对时临时定位 X 到对应 B 范围、A 留在所选 PDF 页，显示关联状态，退出关联后恢复联动。
- 扫描、候选与高亮均为只读提示，不改 B 内容、字符归属、校对状态或分页。
- 当 PDF、B 工作稿或任务 generation 改变时，清除旧映射和动画，拒绝迟到的匹配结果。

## 非目标

- 不宣称 OCR 输出或算法分数是原文正确率。
- 不实现逐字图像坐标到 B 字符的几何连线；OCR 目前只给版面块坐标，字符范围只在块内归一化文本中。
- 不自动补写非空 B 页、提交页面边界、确认校对页或改写 Markdown。
- 不为歧义匹配额外调用生成式 AI；继续使用可解释的文字、路径与切点证据。
- 不替换当前 PaddleOCR 云端服务、任务恢复或凭据存储实现。

## 现状与约束

- `internal/textalign.Align` 已对每页建立 B 候选，再以跨页顺序约束选择路径，并能计算局部 `BoundaryAfter` 切点包络。结果包含 `Selected`、候选、按 OCR `BlockID` 关联的 `Evidence.Range`、页状态和锚点。
- UI 在 [proofread_ocr.go](../../../internal/desktopui/proofread_ocr.go) 的 OCR worker 中调用 `textalign.Align`，但只将结果放入状态；[proofread_ocr_overlay.go](../../../internal/desktopui/proofread_ocr_overlay.go) 目前只画 OCR 块框及 OCR 阶段的扫描线，未画 B 对应范围。
- B 的工作文本是由格式适配器产生的可校对文本流；范围用 Unicode rune 偏移。X 页有连续的内容起止偏移与有限编辑器窗口，可将全局范围映射到一页或多页。实现不得把 rune 偏移当 UTF-8 字节偏移。
- A 与 X 平常共享滚动位置。只在用户查看某条 OCR 对应时短暂进入关联比对：保持 A 来源页，独立滚动 X 到目标范围；用户解除关联时恢复原有同步行为。编辑稿发生变化时取消关联并依现有规则使 OCR 结果失效。
- `textalign` 先逐页候选搜索，再进行全局路径与锚点细化；因此新增进度应明确代表当前候选搜索页，最终匹配状态只在全局路径完成后发布。
- 当前指定书前六页的试验结果为 P1/P3 待确认、P2 未找到、P4–P6 有连续但未完全确定的证据。第一版必须忠实呈现这些结果，不为通过 UI 演示而强行选中。
- 最新提交 `fed4c5e (OCR缓存)` 已增加 OCR 页本地缓存：以 PDF 内容哈希、模型、OCR 选项和页数校验整本结果。缓存只在完整 OCR 页集写入后标记完成；中断的云端任务仍靠持久化 job ID 恢复，并非逐页本地断点缓存。
- 缓存内容是 OCR 原文与版面，不含 B 稿对应结果。缓存命中时必须跳过凭据查询和云端 OCR，但仍按当前 B 草稿重新运行对齐；B 修改不能让同 PDF 的 OCR 页缓存失效。

## 方案

1. **只加对应高亮。** 复用 `Evidence.Range`，点 A 框后定位 X。这最快，但整本首尾与匹配过程仍不可见，也难解释不同页的候选链。
2. **只加强首尾算法。** 改进首尾锚点后输出边界，但没有界面证据帮助用户核查，风险是算法结论仍像黑盒。
3. **首尾、进度和联动比对形成一个小闭环（已选）。** 复用现有单调页路径与切点包络，新增真实页级匹配进度、首尾锚点摘要、证据高亮和短暂关联比对。这个方案直接呈现算法已知与未知的部分；代价是需要处理 A/X 临时独立滚动和高亮范围跨多个 X 页。

## 用户流程与显示行为

1. 点击 AI 扫描后先检查本地 OCR 页缓存。缓存命中时直接用缓存 OCR 进入文字对应，跳过令牌和网络；未命中或缓存不可用时沿用现有远端 OCR、令牌与可恢复任务流程。远端任务仅在 OCR 完整完成后写入可复用的整本缓存。
2. OCR 页数据就绪后，统一进入“文字对应”阶段。无论来自本地缓存还是刚完成的云端 OCR，算法都通过同一个可选进度回调报告正在搜索的 A 页；状态显示 `当前页/总页数`，A 当前页 OCR 区域出现低干扰扫光。没有返回候选前，不在 B 上画假对应。
3. 全局路径和切点计算完成后，UI 展示首个、末个可信锚点（A 页与 B 的 X 页/字符范围），以及全部 A 页状态。未找到锚点时明确显示“未定位”，不把物理首尾当作匹配首尾。
4. `matched` 页以对应色显示 OCR 块与 B 证据范围；短暂同步脉冲后保留淡色范围标记。点击一个有 `Evidence` 的 OCR 块，A 保持该来源页，X 临时滚至对应 B 文本。若证据跨 X 页，显示涉及的页范围并高亮各段交集。
5. `ambiguous` 页标为待确认，只突出当前候选并显示候选序号/数量；用户可切换候选。候选标记始终与 `matched` 区分。`unmatched` / `limited` 不产生 B 高亮。
6. 页间边界显示 `point`、可能切点 `range` 或“无法判断”。即使为 `point` 也只供核对，不自动移动 B 的页面归属。
7. 取消关联、选择另一个 A 页、切换过滤范围或编辑 B 时，按定义退出或失效关联状态；正常 A/X 同步导航继续可用。

## 算法与接口决策

- 不另写贪婪页配对器。当前全局路径会允许跳过 A 页、要求所选 B 区间单调且不重叠，能表达封面/书目未匹配后在正文恢复。首尾锚点从全局结果中筛出：最早/最晚具有可用 `Selected` 与证据的 A 页；状态仍为 `ambiguous` 的锚点不得称为确定锚点。
- UI 展示现有 `BoundaryAfter` 包络；若端点缺少双侧锚点、存在未识别图片或算法预算不够，显示 unresolved，不推断 B 开头/结尾。
- `textalign.Align` 的进度回调只报告候选搜索期间的页索引/总页数。回调可为空；必须可取消且不能阻塞算法。全局路径/边界结果仍一次性发布，避免把中间候选呈现成最终答案。
- 对齐不进入 OCR 页缓存：缓存命中和云端新结果都使用当前 B 草稿重新计算。缓存读失败/校验不通过视作未命中并回退到现有远端流程；缓存写失败不丢弃本次 OCR 或对齐结果，只显示可理解的状态。
- 点击块时以 OCR `BlockID` 找该候选的 `Evidence.Range`，用 rune 区间与当前 `pageOwnership` 求交，将区间转为 X 编辑器窗口局部 rune 区间。仅使用只读视觉叠层，不改 Gio 编辑器选择/caret/文本。
- 在任何跳转/绘制前校验当前 A/B 哈希、工作稿快照、OCR generation 与页面所有权版本；不匹配时清空关联。
- 动画遵循 reduce-motion 不可用时的低频短扫光默认值；窗口/标签不活跃、用户取消、任务结束或窗口关闭时停止定时帧刷新。动画只表示当前处理页，不表示置信度。

## 验收标准

- 算法单测证明进度按候选搜索的真实页序递增、页总数正确、取消可立即停止、空回调可正常运行；现有匹配结果在加回调前后相同。
- 缓存集成检查证明完整缓存命中时不查询凭据/启动远端任务，B 草稿变化会复用 OCR 页但重新计算匹配；缓存未命中或无效时继续既有可恢复云端任务流程。缓存命中与新 OCR 页产生一致的匹配进度与结果。
- UI 测试证明 `Evidence.Range` 在 rune 与 X 页范围间正确转换，覆盖汉字/非 BMP 字符、跨 X 页、空页、已滚动编辑器窗口和草稿更新后失效。
- 交互/视觉测试证明匹配中扫光只在当前 A 页出现；完成后 A 块与 X 对应范围状态一致；歧义候选可切换且不误标 matched；退出关联恢复原始 A/X 同步；底层文本/字符所有权不变。
- 指定书的前六页结果显示为 P1/P3 待确认、P2 未找到、P4–P6 有限度的连续证据；开头和末尾锚点按数据呈现，无硬编码页号。
- 实际 UI 验证从授权目录启动新进程，明确观察 OCR 匹配动画、选择 A 框、X 定位、候选切换、解除联动与取消任务。记录哪些完整书籍页面未覆盖；单测/布局渲染不替代真实窗口观察。

## 风险与缓解

- 首尾书页可能是封面、目录或缺页：显示第一个/最后一个可定位锚点，而不是强迫 P1 对 B 起点、PDF 末页对 B 末尾。
- 语义化 X 文本可能跨多个页或被编辑：用连续 rune 区间及页范围求交；哈希、generation 与所有权校验阻止陈旧跳转。
- A/X 临时解耦可能让用户迷失：清楚显示关联状态及 A/B 页号，提供显式解除动作；退出时恢复同步。
- 全书多页动画可能刷新过密：仅在活动标签和可见 A 页布局动画；匹配进度更新不高于实际页完成频率。
- OCR 块不提供精确字词图像坐标：交互粒度保持块到 B 字符范围，UI 不画伪精确逐字连线。
